# 2026-07-27 工作日志

## 代码评审：错误上报系统

对新增的错误上报系统做了一次全面深度代码评审，覆盖 ~1700 行新增代码：
- `src-tauri/src/main.rs` (Rust 客户端 panic 捕获 + 上报逻辑)
- `server/error-server.js` (自建 Node.js 错误收集服务)
- `server/sentry-webhook.js` (Sentry → GitHub Issue 转发)
- `cloudflare-worker/worker.js` (Cloudflare Worker 版)
- `test-error-report.js` / `test-server.js` (测试文件)
- `src/index.html` 前端全局错误捕获集成
- `.gitignore` / `Cargo.toml` / 配置文件

### 评审结论
- 发现 **25 个问题**：P0×4, P1×6, P2×9, P3×6
- 最严重：XSS 漏洞（Web UI 未转义 app_version/os/count 字段）+ 无认证上报端点 + 生产 URL 硬编码 + .env 未被 gitignore
- `error-server.js` 是问题最密集文件（13 项）
- 产出报告：`doc/CODE_REVIEW.md`
- 用 Chart.js 做了风险分布堆叠柱状图，SVG 做了 XSS 攻击路径图

### 关键发现
1. Cloudflare Worker 公网暴露 + XSS + 无认证 = 可被直接利用的攻击链
2. 哈希算法两套不一致（MD5 vs SHA-256），去重逻辑不统一
3. sentry 依赖无条件编译进 exe，增加体积（用户对体积敏感）
4. test_error_report 命令在 Release 也可调用，可被用来灌垃圾数据
5. error_details 表无清理机制，高频错误会填满 D1 免费配额
