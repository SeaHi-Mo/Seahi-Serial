# 2026-07-28 工作日志

## 内存优化专项评审

对 Seahi-Serial 做了内存优化专项评审，覆盖 Rust 后端（~2000 行）和前端 JS（~4500 行）。

### 评审产出
- 报告文件：`MEMORY_OPTIMIZATION_REVIEW.md`
- 发现 6 个 P0 级 + 10 个 P1/P2 级优化点

### P0 级发现（影响最大）
1. **DOM 行数上限 100,000 行** — 单监视器可达 300,000 DOM 节点，占 60-150 MB，建议降到 10,000
2. **IPC 二进制数据经 JSON 序列化** — `Vec<u8>` 每字节膨胀 ~4x，建议改 base64 或 ArrayBuffer
3. **10ms 轮询** — 空闲时 200 次/秒 IPC 调用，建议改用 Tauri Event 推送
4. **`Array.from(bytes)`** — Uint8Array 转普通数组，体积膨胀 8-16x
5. **读取线程 `to_vec()` 冗余拷贝** — 每批数据拷贝两次，可零拷贝
6. **`send_data` 接收 `Vec<u8>`** — 同 P0-2，发送路径也有 JSON 序列化膨胀

### P1 级发现
- `match_condition` 每次调用 `String::from_utf8_lossy`（N×M 次分配）
- `check_workflows` 每次深拷贝规则快照（可用 Arc 化）
- `le_bytes` 每次创建新 Vec（可用 `&[u8]`）
- `bridge_command` 每次 spawn 新线程
- RegexCache 无淘汰策略
- `parse_hex_bytes` 创建中间 String
- `getOutputText` 全量遍历 DOM
- `bytesToHex` 创建中间数组
- `parseAnsi` 字符串拼接
- `updateLineNumbers` 全量遍历（可用 CSS counter）

### 架构级建议
1. Tauri Event 替代 10ms 轮询（最大收益）
2. 前端虚拟滚动（恒定 ~200KB 内存）
3. Rust 侧对象池/arena allocator
