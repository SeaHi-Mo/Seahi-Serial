## 复验方法（给后续）

1. 打开蓝牙面板 → `开始扫描` → 观察列表与广播内容是否正常。
2. 连接一台**同时支持 write 与 write_without_response** 的特征（如 Nordic UART 的 RX 特征），
   用写入窗口发 `0102`（HEX），确认提示「发送成功」且日志有 `[发送]/[发送成功]`。
3. 连上后切到串口页停留 **≥150 秒**再切回，确认仍为「断开设备」（fork 补丁 3）。
4. 断开后**立即**重连同一设备并发送，确认不出现「该对象已经关闭」（fork 补丁 4）。
5. 设备关机/移出范围，确认约 3 秒内自动变为「连接设备」并有提示（表 15）。
6. 任一步失败时抓 `%TEMP%\seahi-serial-debug.log`，关键行：
   `ble_connect:` / `ble_refresh_rssi:` / `链路已断（设备侧断开）` / `复用上次断开保留的外设对象`。

## 已知环境特征（不是缺陷）

- 附近相当比例的 Random 地址设备会**轮换地址**，旧地址之后必然连不上（报 `Device not found`）。
  应用已把该错误本地化为「设备已离线或地址已变化：随机地址设备会轮换地址，请重新扫描后再试」。
- 连接成功后设备**可能停止广播**，此时它不在扫描结果中（应用会把它补进列表并标注「已连接」）。
