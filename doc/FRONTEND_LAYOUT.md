# 前端目录结构（拆分说明）

> 面向改前端的人。**前端没有构建步骤、没有框架、没有打包器** —— 这一条从拆分前到现在都没变，
> 拆分方式就是为了保住它。

## 1. 为什么拆

原前端是**一个** `src/index.html`（15874 行：1 块内联 `<style>` + 1 块内联 `<script>`）。
十几万行字符挤在一个文件里，改任何一处都要在 1.5 万行里滚，diff 也永远只显示"某一行变了"，
看不出改的是哪个功能。

现在拆成 **4 个 CSS + 14 个 JS + 269 行骨架**，按功能分文件。**拆的是文件，不是架构**：
所有代码仍在同一个全局作用域里，行内 `onclick` 与既有函数互相调用照旧。

## 3. 三条硬规矩（拆分的全部意义就在这三条）

1. **只用普通 `<script src>`，绝不用 `type="module"`。**
   模块有独立作用域，所有行内 `onclick`（拆分时 51 处 HTML + 151 处动态拼接的模板串）会立刻失效，
   而且会退化成"点了没反应"这种最难查的故障。同理 CSS 用 `<link>` 而不是 `@import`。
2. **顺序不能乱调，而且"顶层代码"只能依赖本文件/更早文件里的东西。**
   这条比看起来严格：在**同一个** `<script>` 里，`function f(){}` 是**提升**的 —— 顶层代码写在文件开头也能调用文件末尾声明的函数；
   拆成 14 个脚本之后，提升**不再跨文件**，同样的调用会变成 `ReferenceError`。
   CSS 同理：层叠靠顺序（主题变量必须最先加载）。
   ⚠️ **被 `try { … } catch` 包住的初始化代码最阴**：ReferenceError 会被吞掉，应用照常启动，
   只是那块初始化悄悄不生效（主题没应用、监听没注册）。**别把初始化代码包进 try/catch**，除非你确定失败可以忍受。
   拆分时专门扫过一遍（一次性脚本，已删除）：14 个文件的**列首可执行语句**只有 3 处 ——
   `00-bootstrap.js` 的 `new TextDecoder()`、`70-config.js` 的 `applyTheme(getSystemTheme()) / syncThemeUI()`（它们都定义在**同一个文件的上方**）
   与两处 `setTimeout(...)` 回调（在所有脚本加载完之后才跑）。顶层字面量里唯一"引用了更晚文件"的是
   `30-mcp.js` 的 `MCP_SERIAL_FUNCS.clear`，但那是个**函数值**（调用发生在运行时，不是初始化期）。
   要加新的顶层调用，先确认被调函数在**本文件之前**已经声明。
3. **不引入构建步骤。** 没有打包、没有转译、没有 minify：`frontendDist` 就是 `../src`，
   Tauri 把整个目录原样打进 exe。加一个构建器就意味着"运行的不是仓库里那份代码"。
   ⚠️ 同理**加新文件不用注册到任何清单**：`src/index.html` 的标签列表就是唯一的清单 ——
   编号插在语义相邻的位置（`55-`、`84-` 这样），同时把标签写进 `index.html`。

## 4. 断言集怎么看这些文件

`.walkthrough/gen_ble_preview.js` 里几百条断言有大量**跨 CSS/JS 的源码正则**
（例如"`.qcmd-goto` 这个类有没有定义""后端发的每个 `op` 前端有没有对应分支"）。
它们的本意是"这段内容在前端里"，而不是"它写在内联标签里"。

所以断言集不去读单个文件，而是走 `readFrontendSource()`：读 `src/index.html` 骨架，
再**按标签顺序**把 `css/*.css`、`js/*.js` 内联回去（`<style>…</style>` / `<script>…</script>`），
拼成一个"逻辑单文件"。顺序不变 ⇒ 正则行为与拆分前完全一致 ⇒ **拆分时一条断言都没改**。
`vendor/xterm/*` 不内联（它本就是外部文件）。加新前端文件**不用改断言集**，只要标签写进 `index.html`。

## 5. 新代码放哪一块

| 你要加的东西 | 放哪 |
|---|---|
| 某个面板的样式 | 对应面板的 css（新面板就新建一块，编号插在相近位置） |
| 某个面板的行为 | 对应面板的 js |
| 跨面板的纯工具函数 | `40-utils.js` |
| 启动 / 初始化 / 窗口控制 | `00-bootstrap.js`（早）或 `90-init.js`（晚，DOM 之后） |
| 给 AI 用的语义层（MCP） | `30-mcp.js` |
| 两处都要用的常量 | 放在**第一个**用到它的文件之前（普通脚本没有 hoisting 跨文件） |
