# 快速指令文件（`quick-cmds.md`）格式说明

快速指令分栏里的列表可以**存成一个文件**，这个文件就是列表的"存储"：

> 导入之后，面板里的**增、删、改都会写回这个文件**（去抖约 0.6 秒）。
> 反过来说：你可以直接用编辑器写这个文件，面板会照它显示。

- 入口：分栏右上角「**导入**」（挂载一个文件）/「**导出**」（另存一份副本）
- 挂载后标题下方会出现来源行：`文件名` + 「重载」+ 「断开」
- 能选的后缀：`.md` / `.markdown` / `.txt` / `.tsv` / `.csv`（内容格式见下，与后缀无关）

---

## 一、三种写法（载体）

| 载体 | 长这样 | 说明 |
|---|---|---|
| **Markdown 表格** | `\| 指令 \| 顺序号 \| 超时(ms) \| HEX \|` | 推荐。**只有它能表达"列"与"分组"** |
| **TSV** | `AT+GMR⇥1⇥1000⇥true` | 从 Excel 直接粘贴 |
| **纯指令行** | 一行一条：`AT+GMR` | 最简。放不下参数/分组时，导出会升级成 Markdown 表格并提示 |

载体是**读文件时自动识别的**（含 `|` 的行按表格、含制表符的按 TSV、其余按指令行），
写回时沿用你那份文件的载体。换行统一写成 CRLF。

---

## 二、列：**表头驱动**（最重要的一条规则）

**表头写了列名，那一列才会被当成那个参数**；没写的列一律当作你的备注，原样保留。

| 列 | 认得的列名（不区分大小写，会抹平空格与 `(ms)` 这类括注） |
|---|---|
| 名称 | `名称` `名字` `标签` `指令名` `name` `label` `title` |
| 指令 | `指令` `命令` `内容` `指令内容` `发送内容` `cmd` `command` `value` `data` |
| 顺序号 | `顺序号` `顺序` `序号` `次序` `序` `order` `seq` `sequence` |
| **超时** | `超时` `超时时间` `超时毫秒` `等待` `等待时间` `timeout` `wait` |
| 期望 | `期望` `期望值` `响应词` `成功词` `expect` —— **面板上没有这一列**，见第四节 |
| 重试 | `重试` `重试次数` `retry` `retries` —— **面板上没有这一列**，见第四节 |
| 成功跳转 | `成功跳转` `成功后` `成功` `success` `okgoto` —— **面板上没有这一列**，见第五节 |
| 失败跳转 | `失败跳转` `失败后` `失败` `fail` `errgoto` —— **面板上没有这一列**，见第五节 |
| HEX | `hex` `hex开关` `十六进制` `格式` `format` `mode` |
| 延时（**旧名**） | `延时` `延迟` `延时时间` `延时毫秒` `间隔` `delay` `interval` `ms` `delayms` |

> ⚠️ **`延时` 是旧列名，现在按「超时」解读。** 这一列以前是"这条发完等多久再发下一条"，
> 现在是"这条发出去最多等多久（等到 OK / 超时终止）"——**数值不变、含义变了**。
> 导入这类文件时面板会**提示一次**（不做静默变更）。想自己掌控就把它改名成 `超时(ms)`。
> 两列都写了时以 `超时` 为准。

### 没有表头的老文件（或表头没写全）

- **第 1 列 = 名称，第 2 列 = 指令，第 3 列起是备注** —— 原样保留，绝不按列号硬塞参数。
- 刻意**不认**的列名：`编号` `no` `num` `index` 等。
  它们在中文表里通常是你自己的 ID 列，一旦认成"顺序号"就会把 `A1` 改写成 `0`（真丢数据）。

### 写回**不擅自补列**

你的表头没写 `顺序号 / 超时(ms) / HEX`，写回就一个字都不加（表结构由你定）。
这种情况下这三项**只保存在本机配置里**（`%APPDATA%\seahi-serial\config.json`），
导入时会**提示一次**；想要一份自包含的文件，用「导出」。

## 三、分组：**一组一张表**

```
## 初始化
| 顺序号 | 指令 | 超时(ms) | HEX |
| --- | --- | --- | --- |
| 1 | AT+GMR | 3000 | false |
| 2 | AT+RST | 5000 | false |

## 轮询
| 顺序号 | 指令 | 超时(ms) | HEX |
| --- | --- | --- | --- |
| 1 | AT+CIFSR | 3000 | false |
```

- **两个及以上 `#`** 开头的一行 = 组抬头（`## 初始化`）；**单个 `#` 仍然只是注释**。
- 抬头下面的那张表 = 这一组；每组**各自声明列**（不同组可以用不同的列）。
- **没有抬头的老文件 = 一组**（名字由面板补一个默认名），文件**一字不动**。
- 抬头留空（`##`）时，组名由面板补成「循环 N」。
- 组的**上下顺序 = 循环顺序**：面板里拖动抬头调顺序时，文件里这几张表也会跟着换序。
- 只有一组时，写回**不写抬头**；「导出」的副本则**一定写抬头**。

## 四、每一列的值

| 列 | 取值 | 缺省 |
|---|---|---|
| 指令 | 原样发送。**不按逗号切分** —— `AT+CWJAP="ssid","pwd"` 是安全的 | 空 = 该条不发 |
| 顺序号 | `0` = 不参与循环；`>0` 参与，**组内**按数字从小到大发（同号按行序） | `0` |
| 超时(ms) | 这条发出去**最多等多久**（毫秒），上限 `600000`（10 分钟）。`0` = 这条**不等响应**，发完就发下一条 | `3000` |
| 期望 | **追加的"成功词"**，多个用 `\|` 分隔（如 `WIFI GOT IP\|OK`）。留空 = 只用内置的 `OK` | 空 |
| 重试 | 收到 `ERROR` 后最多**重发几次**，上限 `10`。`0` = 不重发 | `3` |
| 成功跳转 | 收到 `OK` 之后去哪：留空/`下一条` = 顺序走；数字 = **跳到那个顺序号**；`结束` = 收尾停下 | 空（下一条） |
| 失败跳转 | **`ERROR` 用完或超时**之后去哪：取值同上 | 空（终止整条链） |
| HEX | 按 HEX 解析后发送。**读**的时候宽容：`true` `1` `hex` `是` `√` `十六进制` 都算开，其余算关 | `false`（关） |

- 顺序号/指令里可以写 `\|` 来转义竖线；单元格内容不含换行。
- HEX 列**写回**时统一成 `true` / `false`（它就是个开关）。

### 循环发送怎么走（超时那一格说了算）

点「循环发送」之后，一条一条来：

```
发一条 ──▶ 等回应 │ busy  ──▶ 继续等（不重发）
                  │ OK    ──▶ 按「成功跳转」走（默认下一条）
                  │ ERROR ──▶ 重发本条（到「重试」上限）
                  └ 等满「超时」或重试用完 ──▶ 按「失败跳转」走（默认终止整条链）
```

- 超时填 `0` 的行**不等回应**（连续 HEX 帧、或设备本来就不回 OK 的指令用）。
- 终止时面板会说清**是哪一组第几条、等了多久**，循环发送的开关也跟着熄灭。
- `busy` 只算"还在处理"，不会重发，也不会当成失败。

### 跳转：分支与循环（第五节的表头列）

「成功跳转」「失败跳转」两列让**一张表**就能表达流程，不需要另学一套语法：

```markdown
| 顺序号 | 指令 | 超时(ms) | 重试 | 成功跳转 | 失败跳转 |
| --- | --- | --- | --- | --- | --- |
| 1 | AT | 3000 | 3 | 下一条 | 结束 |
| 2 | AT+CWJAP="a","b" | 8000 | 2 | 3 | 1 |
| 3 | AT+CIFSR | 3000 | 1 | 2 | 结束 |
```

- 取值只有三种：**留空或 `下一条`**（顺序走）、**数字 = 顺序号**（跳到那一条，跨组也行）、**`结束`**（收尾停下）。
- 上面这段的意思是：配网（顺序号 2）成功就去查 IP（3），查完回到 2 轮询；**配网失败就回到 1 重来**。
- ⚠️ **超时也算失败**（不只是 `ERROR`）：配网失败多半是超时，只认 `ERROR` 的话这个功能就没用。
- ⚠️ 两列都是"只会打转"的语法，所以有护栏：**连续跳转超过 200 次**（中间只要有一步是顺序走就清零）
  会**自愈停止**并说明"顺序号 N 附近形成了死循环"。
- 目标顺序号不存在时：**导入时提示一次**；真跑到那一步会**降级**（成功跳转按"下一条"、失败跳转按"终止"）
  并把原因写进输出区 —— 绝不静默乱跳。
- 认不出来的写法（比如把顺序号写成 `第一步`）按"下一条"处理，导入时提示一处。

> 想要"图"的话：这两列**就是**流程本身。以后如果真需要画出来，那也只是把这张表**渲染**成图
> （只读视图），不会引入第二套执行方式。

## 五、注释与文件头

```markdown
---
title: Ai-WB2 出厂检查
baud: 115200
---

# 这条是注释（单个 #）
// 这条也是注释

| 顺序号 | 指令 | 备注 |
| --- | --- | --- |
| 1 | AT+GMR | 出厂版本 |
```

- `#`（**单个**）或 `//` 开头的行 = 注释，**按原位置原样保留**。
- **文件头**：首行是 `---`（YAML）或 `+++`（TOML）时，到配对收尾行为止**整块原样保留但不解释**。
  其中 `baud` / `mode` / `lineEnding` / `delay` / `expect` / `timeout` / `hex` 会**提示"暂不生效"** ——
  它们是**每条自己**的设置，得写在表头声明的**列**里（`超时(ms)` / `期望` / `重试` / `HEX`），
  写在文件头这一层不生效（不做静默 no-op）。
- 收尾行缺失时会提示，并按"只有第一行是文件头"处理，正文照常解析。

## 六、写回规则（为什么你的文件不会被重排）

1. **块序列**：注释、表头、`| --- |` 分隔行、第 3 列起的备注，全部按**原位置**保留；
   原本只写一列的行也不会被补成两列。
2. **没动过的格子原样回吐**：你在参数格里写 `0` / `是` / 留空，写回还是那些字；
   只有你**真改了值**（或面板新建的行、导出的副本）才规范化成 `0 / 1000 / true|false`。
3. **空的条目**：整行都空的条目不写回；但**参数格有值的空指令行会保留**
   （否则"面板 7 行、文件 4 行"就对不上了）。
4. **原子写 + 冲突检测**：写回先比对内容哈希 —— 文件被别的编辑器改过就**报冲突**、不静默覆盖。
5. **只有成功读过一次**（手里有哈希）的挂载才允许写回；读不到/被删/超限时宁可不写并提示。
6. **编码沿用读入时的那套**：UTF-8（含 BOM）优先，失败回退 GBK —— 中文不会写成乱码。

## 七、导出 vs 写回

| | 写回（挂载的那个文件） | 导出（另存一份副本） |
|---|---|---|
| 列 | **不补列**，完全按你的表头 | **一定**写 `顺序号 / 指令 / 超时(ms) / HEX / 期望 / 重试 / 成功跳转 / 失败跳转` |
| 抬头 | 只有一组时不写 | **一定**写（`## 组名`） |
| 行数 | = 面板上的条数 | = 面板上的条数（空条目也占一行） |
| 名称列 | 原样保留 | **不带**（面板里没有名称入口，副本与面板一一对应） |
| 载体 | 沿用原载体 | 纯指令行放不下时会升级成 Markdown 表格并提示 |

导出默认文件名：主分栏是 `quick-cmds.md`（TSV 时 `quick-cmds.tsv`）；**WSL 分栏 / 额外分栏 / 蓝牙页内嵌
监视器各有自己的一份快速指令列表**，它们的默认名会带上自己的标识（`quick-cmds-wsl.md`、
`quick-cmds-extra-1.md`、`quick-cmds-ble-mon.md`）—— 免得"连点两次导出、都存到同一目录"时第二次盖掉第一次。

> ⚠️ 导出是**直接写文件**（它是"另存一份副本"，不走写回那条哈希冲突检测）。所以别把它存成
> **另一个监视器正挂载着的那个文件** —— 那会把那边的内容当场换掉（面板会提示你，但最好换个名字）。
> 另外同**一个文件不能被两个监视器同时挂载**：第二次「导入」会被拒绝，并告诉你先去哪边「断开」。

## 八、上限

| 项 | 上限 | 超了会怎样 |
|---|---|---|
| 文件大小 | 256 KB | 读/写都会被后端拒绝（并提示） |
| 条目数 | 500 条 | 多出来的行**跳过**并在导入时提示 |
| 名称 | 64 字符 | 截断并提示 |
| 单条指令 | 4096 字符 | 截断并提示 |

上表是**读入端（导入/重载）**的行为。**在面板里新增、编辑同样受这几条上限约束**（AI 通过 MCP
改这个列表时也是同一条路）：

- 到 500 条就**加不进去了**，会明确提示"先删掉几条"；
- 单条内容超过 4096 字符会被**拒绝并提示**（不是静默截断），组名超过 64 字符同理。

为什么写入口也非拦不可：如果只靠"读入时截断"，内存里就会存在一条比文件上限更长的指令，写回去的
文件随之超限、下次重载又被截断 —— 之后**每一次写回都会用"截断后的内容"整份覆盖你的文件**，
多出来的部分就永久丢了。

## 九、完整示例

```markdown
---
title: Ai-WB2 出厂检查
baud: 115200
---

// 上面这两行会被提示"暂不生效"：波特率在面板上设

## 1. 初始化
| 名称 | 指令 | 备注 | 顺序号 | 超时(ms) | 期望 | HEX |
| --- | --- | --- | --- | --- | --- | --- |
| 复位 | AT+RST | 这一步最慢，最多等 5 秒 | 1 | 5000 | | false |
| 查版本 | AT+GMR | | 2 | 3000 | | false |
| 进透传 | AT+CIPSEND | 手写备注列也保留 | 3 | 3000 | | false |

## 2. 轮询
| 顺序号 | 指令 | 超时(ms) | HEX |
| --- | --- | --- | --- |
| 1 | AT+CIFSR | 3000 | false |
| 2 | 01 02 03 04 | 0 | true |
```

面板读进来就是**两组、共 5 条**：第一组按顺序号 1→2→3 发（每条发完等它的回应，收到 OK 才走下一条），
然后进第二组，走完第二组回到第一组（循环顺序 = 组的上下顺序；抬头可以在面板里拖动换位）。
第二组第 2 条的超时是 `0` —— 那条不等回应，发完就走（HEX 裸帧没有 OK）。

## 十、常见问题

**Q：我在第 3 列写了备注，导入后它变成"顺序号"了？**
不会。只有表头**写了列名**的列才会被当成参数；你的表头没写 `顺序号`，第 3 列就是备注。

**Q：面板里改了，文件没变？**
看提示。最常见的原因是这份文件**还没成功读过一次**（比如路径失效、文件被删、超过 256 KB）——
没有内容基线时宁可拒写，也不会拿内存里的列表把你文件重写一遍。点「重载」或重新「导入」即可。

**Q：导出后怎么多了一列 / 多了一行抬头？**
导出的是**自包含副本**：一律补齐 `顺序号 / 指令 / 超时(ms) / HEX / 期望 / 重试` 六列，并且写 `## 组名`。
写回你的挂载文件时不会做这两件事。

**Q：为什么导入后少了一条？**
整行都空的条目会被跳过（写回时也不会写它）。如果你的那行只是"还没填指令"，
但**参数格有值**（比如 `|  | 0 | 3000 | false |`），它会被保留成一条。

**Q：我的老文件里那一列叫「延时」，现在怎么办？**
能用，但**含义变了**：它现在被当成「超时」——那条指令发出去最多等这么久，等不到 OK 就终止循环。
导入时面板会提示一次。老值太小（比如 `1000`）容易误判超时，建议改成 `3000` 以上，
或者干脆把列名改成 `超时(ms)` 免得下次又记混。

**Q：一条指令设备就是不回 OK（或者回的是别的词）怎么办？**
两种办法：① 把这条的**超时填 `0`** —— 它发完就走，不等回应；
② 如果设备回的是 `WIFI GOT IP` 这类词，就在表头加一列 `期望`，把词写进去（多个用 `|` 分隔）——
内置的 `OK` 仍然认，`期望` 是**追加**。这一列**面板上不显示**（改它要编辑文件），
所以面板会在超时那一格上描一道淡边、悬停能看到具体内容；导入时也会提示一次。

**Q：组名能在文件里改吗？**
可以，改 `## 后面的文字` 即可；反过来在面板里改名也会改写这一行。

**Q：`超时` 和 `timeout` 都行吗？**
都行，见第二节的列名表。`超时(ms)` 里的 `(ms)` 会被自动忽略。

**Q：面板上为什么看不到「期望」「重试」这两列？**
它们**只写在文件里**（有些设备回 `WIFI GOT IP` 而不是 `OK`、有些指令要重发更多次才生效），
面板上为它们留了出口：**超时那一格**。给某条写了这两项时，那一格会描一道淡边，
悬停就能看到 `期望 = …、重试 = …`；导入文件时也会提示"有几条写了自定义条件"。
导出（副本）会把这两列**写全**，所以"导出再导入"不会丢。
