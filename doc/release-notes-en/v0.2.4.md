### 🔒 Security fixes

- **XSS**: every user-controlled field of the error management web interface, including `app_version`, `os` and `count`, is escaped with `escapeHtml()`.
- **API key authentication**: the `/report` endpoint accepts an `X-API-Key` header and stays backward compatible when none is configured.
- **CORS is restricted**: `/api/*` is limited to configured origins instead of a wildcard.
- **Sentry webhook signature verification** with HMAC-SHA256.
- **Body size limit**: the reporting endpoint accepts at most 1 MB, preventing denial of service.
- **Debug builds are isolated** and no longer report to the production error server.
- **Sensitive files**: `.env` and `errors.db` were added to `.gitignore`.

### ✨ New

- **Multiple WSL monitors**: the WSL port mapping page can open several serial monitors sharing one device list.
- **A context-aware "open extra monitor" button** creates a main monitor on the main page and a WSL monitor on the WSL page.
- **Automatic frontend error reporting** through `window.onerror` and `unhandledrejection`.

### 🔧 Improvements

- Error reporting uses a channel with a single consumer thread instead of spawning a thread per error.
- The hash algorithm is uniformly SHA-256, matching the Cloudflare Worker build.
- Sentry became an optional feature gate that is not compiled by default, reducing executable size.
- The `error_details` table keeps at most 100 records per error.
- The de-duplication map expires entries after 24 hours, preventing a memory leak.
- The SQLite path is absolute, so it no longer depends on the working directory.
- Frontend reports include the monitor connection state to help reproduce problems.

### 🐛 Fixed

- `renderWslDeviceList` no longer crashes on an undefined `d.vidpid`.
- Custom tooltips are no longer clipped by the screen edge.
- The `test_error_report` command can no longer be called from a release build.
