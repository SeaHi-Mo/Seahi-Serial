### 🐛 Fixed

- **The WSL auto-mapping switch could not change its visual state**: clicking the visible slider triggered row selection, the row list was re-rendered, and the checkbox change event was disturbed, so `toggleAutoMap` did not fire reliably and auto-mapping could not be enabled. The switch and its slider no longer trigger row selection.
- **Serial writes could deadlock**: while the read thread held the port lock, a write command's `lock()` could block forever and freeze the main thread. The lock now has a timeout by polling `try_lock` and returns an explicit error, and the blocking write moved to `spawn_blocking`.
- **WSL commands crossed their output**: concurrent commands on the persistent WSL shell read the same pipe, so command A could receive command B's output. A `WSL_SHELL_CMD_LOCK` now serialises reads and writes.
- **WSL and serial commands blocked the interface**: `list_ports`, `list_wsl_devices`, `check_wsl_status`, `open_wsl_serial`, `read_wsl_serial`, `send_wsl_serial` and `get_wsl_distributions` became async with `spawn_blocking`, so long synchronous commands no longer stall the main thread.
- **Error reporting was wired up** on several frontend and backend paths for remote diagnosis through `reportError` and `report_error`.

### ✨ Improvements

- Every frontend `invoke` now has a timeout fallback through `invokeTimeout`, so the interface no longer waits forever when a backend command hangs, for example an unconfirmed UAC prompt.
- WSL device list refreshes use a single-flight lock, avoiding concurrent rescans and full DOM rebuilds after unmapping.
- WSL sessions are held through `Arc`, so a slow command no longer holds the global lock and blocks other WSL commands.
