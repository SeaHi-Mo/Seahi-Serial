### ✨ New

**Bluetooth host: the real pain points behind "cannot find it" and "cannot connect"**

- **Direct connection by MAC**: once a peripheral has been paired by Windows or taken over by another phone, it often stops advertising, never appears in the scan list and can never be selected. An address can now be entered above the device list and connected with Enter, without relying on advertising at all, using `add_peripheral` from btleplug.
- **The negotiated MTU is shown**: after connecting, the header shows `MTU 185 (payload 182)`, so a failed long write can be told apart from a wrong characteristic.
- **Scan duration is selectable**: 5, 15, 30 or 60 seconds, or continuous, defaulting to 15. It used to be hard-coded at 5 seconds, while low-power peripherals often advertise every one or two seconds or slower, so five seconds frequently caught nothing. Stopping at the end is now reported instead of happening silently.
- **Multiple Bluetooth adapters are supported**: scanning, the device list, signal strength and lookup by address all cover every adapter, and a device heard by several adapters is de-duplicated. Previously only the first adapter was used, so a plugged-in USB dongle had no effect.

### 🐛 Fixed

- **The backend connection had no timeout**, so when the frontend gave up after 15 seconds and the backend connected later, the interface could show disconnected while the link was live. The backend now has an explicit 10-second timeout and disconnects to settle the state.
- **Dropped notifications were invisible**: polling tightened from 400 ms to 250 ms and the buffer grew from 500 to 2000, and the number of dropped entries is now logged, instead of silently discarding the oldest and making the device look quiet.
- The left column width differed between host and peripheral modes and the layout jumped when switching; it is now shared.
- The peripheral panel used the browser's default scrollbar, wide and bright on dark themes; it now matches the log area.

### 📝 Notes

- This release adds the complete BLE peripheral (GATT server) capability: service and characteristic configuration, receiving reads and writes from a central, sending notifications, broadcast configuration import and export, and multiple saved configurations. **The entry point is hidden by default**: on the development machine with Intel integrated Bluetooth, advertising does not work, because frames carrying a service UUID or a local name are rejected with `E_INVALIDARG`, and a GATT server must advertise its service UUID, so it always ends in `Aborted`. The evidence chain is in `doc/BLE_PERIPHERAL.md` §5.
- The code is kept in full: on an adapter that allows such advertising, set `BLE_PERIPH_MODE_ENABLED` to `true` in `src/index.html` to enable it.
