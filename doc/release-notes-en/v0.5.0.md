### ✨ New

**MCP support: AI clients can operate the application directly**

A built-in MCP (Model Context Protocol) server runs inside the application process, listens only on the loopback interface, speaks SSE only, and starts with the application.

- **A new MCP icon in the title bar** sits left of the theme style picker, uses the same colour, and carries a status dot: grey when disabled, green while listening, blue when sessions exist, red when start-up failed. The dialog toggles the server with one button, shows the current URL, and copies either the client configuration or the install prompt. Version, tool count, request count and drop count appear on hover.
- **Starts with the application and falls back on ports**: the default is `127.0.0.1:7777`, and up to twenty further ports are tried when it is taken. The actual port is shown in the dialog.
- **Access token**: generated on first start and carried in the URL, which works with SSE clients that cannot set custom headers. The dialog can reset the token, which invalidates the old one immediately.
- **Endpoint discovery file** `%APPDATA%\seahi-serial\mcp-endpoint.json` for the installer and external tools.
- **33 built-in tools**: thirteen serial semantic tools (select port, set baud rate, frame format, DTR and RTS, start monitoring, send, read back monitored data, clear, history, quick commands, all with a `pane` argument) plus twenty general tools in four groups:
  - Application and server: `app_info`, `mcp_status`, `mcp_limits`, `serial_list_ports`
  - Interface: `ui_list` (every controllable widget with the reason when disabled), `ui_describe`, `ui_get`, `ui_set`, `ui_click`, `ui_get_state`
  - Logs: `log_channels`, `log_tail` (incremental by sequence), `log_search` (substring or regular expression across channels), `log_stats`, `log_clear`, `log_export`
  - Records and configuration: `mcp_calls`, `mcp_stats`, `mcp_config_get`, `mcp_config_set`
- **Interface operations really change the interface**: tools take the same path as a user click through synthesised DOM events, so there is no "the AI changed something that never took effect".
- **Optional tool per widget** (`ctl_xxx`, off by default): enabling `expose.autoControlTools` generates a tool for every button, input and dropdown. It stays off so tool selection accuracy is not diluted.
- **Log centre**: the backend collects application logs, errors, BLE notifications, serial traffic and interface notices. Every channel has a byte cap and a drop counter, so the caller is told how many entries were dropped instead of assuming the log is complete.
- **Memory limits are enforced, not merely reported**: 16 MiB overall (the largest channel is trimmed when exceeded, and both trim count and bytes are queryable), 64 channels (channel names grow with the number of monitors; past the cap no new channel is created and the skip is counted), and each entry is truncated at 8 KiB. None of this blocks the serial read thread, which drops and counts when the lock is unavailable.
- **AI call record**: one line per tool call in `%APPDATA%\seahi-serial\ai-calls.jsonl` (time, session, tool, arguments, outcome, duration and which widgets changed), rotated by size.
- **Companion npm installer** `npx seahi-serial-mcp install` writes the endpoint into client configurations and can be rerun after a port fallback. It has no dependencies and no postinstall, confirms the application is running before writing, backs up before changing, and refuses to rewrite a configuration file that contains comments, offering a snippet to paste instead.
- **Tool list changes are pushed to clients**: when widgets are added, removed or become available, the server sends `notifications/tools/list_changed` to connected sessions, so clients need neither polling nor reconnecting. The sentinel endpoint `GET /healthz` still answers only `{"ok":true}`, and `GET /status` requires a token and masks both the token and the full URL.

**Security boundary**: loopback only and not configurable, a token is mandatory, tools cannot change the token, and AI records live in separate files so `config.json` never contains a trace of AI activity, which an assertion enforces.

- **Efficiency of AI calls**: `initialize.instructions` hands over the working method in one shot (check state first, the main serial flow, error code meanings, limits), so an agent gets it right the first time instead of guessing through failures, and error messages list valid values or the next tool to call.
- **Read-only (sandbox) mode**: one switch in the dialog makes AI able to read but not change anything. Every write tool is refused with `-32007` and neither the interface nor the configuration changes. Only a human can turn it off, because `mcp_config_set` is itself a write tool; the asymmetry is deliberate.

### 🐛 Fixed

**Three long-running defects caused by unbounded memory or disk growth**

- **The debug log grew until the disk filled.** `%TEMP%\seahi-serial-debug.log` had no limit and was appended to on every call, including in release builds. It is now capped at 4 MiB and rotated to `.1`, keeping one backup, and `SEAHI_DEBUG_LOG=0` disables it entirely.
- **The session log cache limited file count but not size.** `%APPDATA%\seahi-serial\log-cache\` kept the last ten files with no per-file limit, which at 921600 baud is roughly 330 MB per hour and gigabytes in the worst case. Each file is now capped at 8 MiB with a 64 MiB directory budget; reaching the cap writes a termination marker and tells the user, instead of stopping silently. Cleanup skips files that are still being written.
- **Interface memory kept growing during long captures**, for three compounding reasons:
  1. The compact buffer was trimmed only at one million lines; it now trims by an 8 MiB budget, halving on overflow.
  2. The data buffer doubled but never shrank after trimming; capacity now follows actual usage.
  3. The output DOM skipped cleanup entirely while the user was scrolled up or had a selection, so rows could grow without bound. It now defers with a hard cap of 60 000 rows and compensates scrolling so the view does not jump, then trims to the normal limit once the selection is gone.
  4. Every monitor preallocated 1.7 MB even while idle, so two monitors cost 3.5 MB of typed arrays; allocation now starts at 64 KB and doubles on demand (about 92 KB per idle monitor), and clearing the output releases the capacity.
- **Two hidden bugs fixed along the way**: the index array of the compact store was replaced without copying, so a resize cleared the row offset table and made save, copy and history load read garbage; this would have hit at 100 000 rows and would have hit at 4096 after the smaller initial capacity, so the copy is restored. Two WSL monitor creation paths omitted the byte budget, which made save and copy all output only the last line; they now set it, with a defensive default.

**MCP: the official SDK was used to call every tool on a running instance, which surfaced four classes of problem before release**

- **Error code routing was completely broken**: the frontend reply dropped a flag, so every "widget path or value does not exist" returned `-32006` ("no interface context") instead of `-32602`. AI therefore believed the interface was closed and retried, when the right action was to fix the arguments. The fix includes a test that covers the whole chain from reply to bridge to error code.
- **Single-target writes reported success on failure**: `ui_click` and `ui_set{path}` hid failures inside per-item results while the top level said success. A failed single target now fails the whole call, batch semantics stay for multiple targets, and the fields that did apply are named in the error.
- **Port listings did not show port names**: the text summary printed `ports=1 item`, and many clients show only that text to the model. The summary now lists the content, and field names are camelCase (`portName`, `friendlyName`, `productName`) with the old snake_case spellings still accepted.
- **The session count in the interface never refreshed**: the server always reported `sessions=1` correctly, but session changes were not pushed to the interface. Every connect and disconnect now pushes, and `mcp_status.statusEmits` makes it observable.
- **A rate-limited call hung until timeout**: the rejection reply carried a `null` id, so the client could not match it, waited for the timeout, retried and made the limit worse. The reply now carries the real request id and states that the call was refused and how to slow down.
- **"Start monitoring" waited six seconds with no device**: it now returns the reason immediately.
- **Tool schema portability**, found by the official MCP Inspector which is now part of the checks: `ui_set`'s parameter schema was an empty `{}`, and after typing it, an array `type` made some clients reject the tool or drop the constraint, so `anyOf` is used. All 33 schemas now pass with zero warnings, and both criteria are fixed as invariants.
- **A switch that could be read but not set**: `serial_get_state` reported `advOpen` while `serial_set_display` could not set it. It can now, and an assertion requires every reported switch to be settable.

### 📝 Notes

- This release contains two independent things: MCP support, which starts with the application, listens only on loopback and requires a token, and can be switched off from the dialog; and fixes for three defects that appear with long use. Either part stands alone, so the release can be taken purely as a bug-fix upgrade.
- The thirteen serial semantic tools (33 tools in total) let AI say "open COM3 at 115200, send AT and show me the reply" instead of assembling widget paths.
- Known gaps, stated plainly: the BLE, ADB and WSL panels have no semantic tools yet and are reachable only through the generic widget bridge, and the serial send and receive chain has not been verified on real hardware, because the development machine has no serial device.
- The MCP server listens as soon as the application starts, on `127.0.0.1:7777` by default, falling back to the next free port and showing the actual one. The same button in the dialog turns it off and on; when off it occupies no port and the log centre closes with it.
- Connection details, the tool list and troubleshooting are in `doc/MCP.md`, with design notes in `doc/MCP_DESIGN.md`.
- ⚠️ **One behaviour change to note**: copy and export all read the compact in-memory store, whose limit changes from one million lines to 8 MiB, roughly 200 000 lines. Sessions longer than that lose their oldest part on export, while the on-disk cache keeps the beginning, so the two truncate from opposite ends. The trade-off is recorded in `doc/MCP_DESIGN.md` §13 D14.
