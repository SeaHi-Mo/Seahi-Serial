### ✨ New

**Quick commands move from a corner icon in the send bar to a collapsible column beside the output area**

- The entry point was rebuilt after usability research found that more than half of users could not find the old unlabelled three-line icon. The column sits to the right of the output area, occupies only the output row and never spans the toolbar above or the send bar below; expanding it only narrows the output area while both columns still fill the pane.
- It is collapsed by default: just a 14 px strip with no icon, no text and no triangle, only a thin centred handle that lights up on hover.
- Expanded, the strip is filled with the theme accent and the handle turns white; all colours come from theme variables, so all twelve themes including the light ones work.
- The width is draggable from 120 to 640 px, always leaving 160 px for the output area, and is stored per monitor in `config.json` and restored on restart.
- The list uses two-line cards, a name row plus a row for the command, so long AT commands stay readable.

**Quick commands can live in an external file, imported, exported and written back**

- Three buttons on the header row: add, import and export. After importing, the source row shows the file name with reload and disconnect.
- The file is the storage: after importing, adding, editing and deleting in the panel are written back to that file with a 0.6 s debounce and an atomic write, so there is no second copy of the truth.
- Three carriers are detected and preserved on write: a Markdown table, TSV, and plain command lines. Splitting on commas is deliberately not done, because commas are normal in AT commands such as `AT+CWJAP="ssid","pass"`, and a file named `.csv` is still read as one command per line.
- Hand-written files are never damaged: comments, blank lines, headers, separator rows and extra columns keep their positions, single-column rows are not padded to two, and malformed or oversized rows are skipped with a line number and reason.
- YAML and TOML front matter is preserved untouched and never read as a command, which would otherwise turn `baud: 115200` into a command and then into a table row on write-back. Keys such as `baud`, `mode`, `lineEnding`, `delay`, `expect`, `timeout` and `hex` are reported as not yet effective, while descriptive `title` and `note` keys are ignored silently.
- Changes made by another program are not overwritten: the content hash is compared before writing and a conflict asks the user to reload. Writing is only allowed for a file that was read successfully once, so a deleted or unreadable file is refused rather than rewritten from memory.
- The encoding of the import is kept: UTF-8 with or without BOM, falling back to GBK, and written back in the same encoding. Limits are 256 KB per file, 500 commands, 64 characters per name and 4096 characters per command, all reported by `mcp_limits`.

### 🐛 Fixed

- **Reinstalling or upgrading failed because adb held its files open.** The adb server runs in the background even after the application exits and keeps `adb.exe`, `AdbWinApi.dll` and `AdbWinUsbApi.dll` mapped, so a running executable cannot be overwritten and loaded DLLs cannot even be deleted. The installer used `ignoreversion` and rewrote all fourteen files unconditionally, which failed after four retries with "error trying to copy the following files". The installer now stops only adb processes whose image path is inside this application's `platform-tools`, at three points, and uses `replacesameversion` with `restartreplace` and `uninsrestartdelete`.
- **The installer could be new while the application inside was old.** The version is baked in at compile time, so editing only the version files leaves an old executable, which once produced an installer labelled 0.5.0 that installed 0.4.0. `installer.iss` now has a compile-time guard that fails with `#error` when the executable version differs from `MyAppVersion`, and the installer's own file version field is filled in.
- **When usbipd was not installed, the wrong task was preselected**: the last task in the list was used as the usbipd task, which pointed at the new ADB PATH task. An explicit index constant is used instead.
- **The ADB PATH entry could duplicate or linger**: trailing slashes and case are normalised before comparing, unchanged values are not written, and paths containing single quotes are escaped safely.

### 🔧 Improvements

- The BLE device column is narrower by default, 288 px instead of a fixed 400 px, giving more room to the GATT detail. Both sides can be resized by dragging, the host and peripheral modes share the width, and the width is persisted.
- The MAC connect placeholder now reads "enter the target device MAC to connect directly".
- `serial_quick_cmd` reports `source` as `file` or `config` plus the file path, so AI knows the list comes from an external file, and `mcp_limits` includes the quick command file limits.
