This release fixes an old problem that only appears with one transport: MCP clients using Streamable HTTP (`/mcp`) do not refresh the session monitor. Clients on the legacy SSE endpoint were unaffected, which is why it stayed hidden, and newer clients such as VS Code, Cline, recent Cursor and Claude Code use `/mcp` by default.

### 🐞 Fixed

**MCP session monitoring did not refresh (title bar indicator and session count in the dialog)**

- Symptom: a client connected, but the indicator at the lower right of the MCP icon never changed, and the "N sessions" line in the dialog stayed where it was, even after opening the dialog.
- Root cause: the `/mcp` transport never notified the interface when a session was created; only a full session table triggered a notification. The interface had only two update paths, a pushed event and a single refresh when the dialog opened, and the indicator had no second path at all.
- Session creation, eviction when the table is full, and idle reclamation now all push the new count, matching the SSE path. HTTP sessions reclaimed while idle are reported too, so the number no longer only grows.
