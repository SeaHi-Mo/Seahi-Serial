This release fixes a problem that only appeared after upgrading to WSL 3.0.3: pressing start or open terminal on a distribution in the WSL panel opened a Windows PowerShell instead of WSL, or the window flashed and closed.

### 🐞 Fixed

**1. WSL error text was parsed as a distribution name**

- Symptom: pressing start on a distribution card opened Windows PowerShell, and a strangely named distribution card appeared in the panel.
- Root cause: after the upgrade, `wsl --list --verbose` returned WSL's own error text (`error code: 0`, `access denied Wsl/E_ACCESSDENIED`, `please open https://github.com/microsoft/WSL/issues`). The old parser took the first word of each line as a distribution name, producing a card named "error code:". Pressing start on it ran `wt.exe -p "error code:"`, and Windows Terminal silently falls back to its default profile, Windows PowerShell, when a profile name does not exist. The same path existed when choosing a distribution for a WSL serial port, and it cached the bogus name, so every WSL serial port failed afterwards.
- Now a line counts as a distribution only if it contains a complete known state word (Running, Stopped, Installing and so on) or a numeric VERSION column. If no line can be parsed, the panel reports an error and shows WSL's original text instead of guessing. Names containing spaces (from `wsl --import "My Distro"`), older WSL 1 distributions, localised state words and systems without a header still work.

**2. Start can no longer open a different profile**

- `launch_wsl` verifies the name against the live distribution list, refusing unknown names and listing the available ones, and passes `wt` an explicit command line: `wt -p <distro> [--startingDirectory …] wsl.exe -d <distro>`. The `-p` argument only chooses the appearance while `wsl.exe -d` decides what actually runs, so the tab runs the right distribution even if the profile name does not match, and a real failure shows WSL's own error rather than a PowerShell prompt.
- The hard-coded `Ubuntu-20.04` fallback is gone; without an explicit distribution the default one is used, and an explicit error is raised when none exists.

**3. Failures are no longer silent**

- When the distribution list cannot be read, the panel shows the reason instead of clearing the area or drawing a fake card.
- Opening the terminal and starting or stopping a distribution now always show a notice; previously they only wrote to the console.

### 📄 Documentation

- The incident chain and the two "do not revert this" rules are recorded in `AGENTS.md` and `doc/ARCHITECTURE.md` §5.8, guarded by five new backend tests and eleven frontend assertions, including compatibility cases such as keeping names with spaces intact and not treating the word "install" inside a sentence as a state word.
