This release ships the community-contributed window position and size memory that was not yet present in the v0.5.1 installer, and fixes the cases where it misbehaved on upgrade and on an abnormal start.

### ✨ New

**Window position and size are remembered** (community PR #20, thanks to @Tom Yin)

- On exit the position, size and maximised state of the main window are written to `%APPDATA%\seahi-serial\window.json` and restored on the next start. Multiple monitors and a secondary screen to the left of the primary (negative coordinates) are supported.
- Dragging and resizing save automatically with a 400 ms debounce, and one forced save happens on exit, so a resize performed just before closing is not lost.
- **Abnormal states never pollute the record**: the transient size the hidden window reports during startup (values such as 2068×2060 have been observed) and the `-32000` sentinel coordinates of a minimised window are never written. Maximising records a flag only, and unmaximising returns to the ordinary size from before, so the full-screen size is never stored as the normal size.
- **Unplugging an external monitor does not lose the window**: before restoring, the stored rectangle must overlap a monitor by at least 60×40; otherwise the window stays centred on the default position instead of being placed on a monitor that no longer exists.
- The main window now restores its geometry first and is shown once afterwards (hidden at startup, revealed when the page is ready), so it no longer flashes at the default size before jumping to the remembered one.

### 🐛 Fixed

- **Upgrading reset the window size once**: versions up to 0.5.1 kept the size in `config.json` as `windowWidth` and `windowHeight`, while this version manages it in `window.json`. When the new file is missing the old fields are used, so the size survives the first start after upgrading; those fields carry no position, so the window stays centred instead of jumping to the top-left corner.
- **Under extreme conditions the application started without a visible window**: when interface initialisation failed or the eight-second watchdog fell through to the error page, the window itself was still hidden, so even that page could not be seen. The fallback page now forces the window to show, and the backend has a four-second fallback of its own.
- The version recorded in `package-lock.json` was corrected from 0.4.0 to the application version; this affects the record only.
