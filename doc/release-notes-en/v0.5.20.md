This release turns terminal mode into a real terminal and fixes a stability problem that could make WSL and USB operations appear to hang until they timed out.

### ✨ New

**1. Terminal mode is a real terminal (xterm.js)**

- The output area becomes a terminal canvas: Enter sends `\r`, Tab sends `\t`, arrow keys send `ESC[A…` and Ctrl combinations are sent unchanged. There is no local echo and no local tab completion; completion and history belong to the device shell, and full-screen programs such as `vi` and `top` work normally.
- Every pane has its own terminal instance, and history survives switching away and back; it is released only when the pane closes.
- Entering terminal mode sends one carriage return to the device, so it reprints its prompt and the canvas is not blank.

**2. Terminal colours follow the interface theme**

- The 16 ANSI colours, background and foreground, cursor and selection all come from the current theme, using the same colour definitions as the normal output area. Twelve combinations (six theme styles, light and dark) are handled, and switching themes takes effect immediately.
- The same colourful log, such as the blue directories and cyan links of `ls --color`, looks identical in the normal view and the terminal view.

**3. Commands typed in the terminal are logged**

- One log entry is recorded when Enter is pressed and one when content is pasted, marked with source `ui`, and both are searchable in the log centre and on the `serial:<pane>:tx` channel. Individual keystrokes are not logged, and escape sequences from arrow keys are never mistaken for typed input.

### 🐞 Fixed

**4. Large output from external commands could hang until timeout**

- When running `wsl`, `usbipd` or `adb`, stdout and stderr are now read concurrently, so output larger than the system pipe buffer no longer blocks the child process, which previously waited until it was killed at timeout with all output lost.
- "Failed to start" and "timed out" are reported separately, and a missing `usbipd` is no longer misreported as a timeout that asks for administrator rights.

### 🧹 Behaviour notes

- **The normal output area keeps the log view**: only the 16 ANSI colours carried by the log itself are themed; 256-colour and true-colour output works only in terminal mode, which supports it fully.
- Terminal command logging records the command text only; device echo and output are still displayed and logged as before.

### 🧪 Internal

- Three backend tests were added (large output does not stall, timeout is distinguishable, start failure is distinguishable); 1971 frontend assertions and 94 installer self-tests pass.
- The `app`, `mcp` and `error` channels of the log centre grow from 128 KB to 512 KB so troubleshooting logs are truncated less often.
- A new issue template; release notes now keep only the current version, and CI verifies the current section exists and is unique.
