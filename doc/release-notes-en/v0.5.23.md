This release turns error reporting on for real: crashes, backend runtime errors and frontend script errors are sent to the author's error collection service so they can be located and fixed. It is on by default and can be turned off with an environment variable. The installer version follows the release.

### ✨ New

**1. Error reporting is on by default**

- Three kinds of errors are covered: crashes (panic), backend runtime errors, and frontend JavaScript exceptions (including unhandled promise rejections).
- What is sent: application version, operating system, error message and stack, and context tags. Serial traffic, log bodies and device data are never sent; a stack may contain code file paths, which help locate the problem.
- The same kind of error is reported at most once every five minutes, which avoids duplicates and server-side rate limiting.

**2. Turning it off**

- Set `SEAHI_ERROR_REPORT=0` before starting (`false` and `off` work as well), or keep it in the system environment variables.

### 🔧 Fixed

**1. Error reporting had never actually worked**

- The documentation said to set `ERROR_SERVER_URL` at build time, but the program read a runtime environment variable: a value set for `cargo build` never reaches the executable, so released builds had never reported anything.
- The endpoint and key are now injected at build time, and can still be overridden at runtime with `ERROR_SERVER_URL` / `ERROR_API_KEY` for local testing or a self-hosted service.
- Development builds never report to production, so debugging cannot pollute live data.

**2. More accurate MCP status**

- `mcp_status` now reports `errorReports.sinkConfigured` from the real enabled state instead of only looking at environment variables.
