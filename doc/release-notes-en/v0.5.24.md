This release narrows MCP transport to a single mode (HTTP or SSE, not both) and fixes several session problems: sessions being reclaimed while still in use, an inflated session count in the UI, and broken connections with no diagnostics.

### ✨ New

**1. Clearer session state**

- The status dot in the MCP dialog now has three states: solid blue when a push stream is active or the session was active within five minutes, a hollow ring when only an idle entry remains, and solid green when no session exists.
- `mcp_status` gains `sessionsDetail` (first eight characters of the session id, kind, idle seconds, whether a push stream is attached), so "actually in use" can be told apart from "just a table entry".

**2. Diagnosable disconnects**

- `mcp_status` gains `recentRejections`: the last 40 rejections (404 / 401 / 403 / 400) with time, path and reason.
- Requesting a transport endpoint that is currently disabled now returns a 404 that states which mode is active and which one to switch to.
- A 429 (session table full) carries `Retry-After` and a suggested action.

### 🔧 Fixed

**1. Clients holding a long connection are no longer reclaimed**

- Previously an SSE session that had not sent a request for 30 minutes could be swept when another client created a session, even though its stream was still open. A session with an active push stream now counts as alive, and heartbeats refresh its activity time.

**2. The UI no longer overstates the session count**

- Only sessions that can still serve requests are counted, every deletion path pushes the new state, and a 60-second idle sweep lets the number fall back once clients leave.

**3. A full session table no longer blocks new clients**

- New connections evict the least recently used HTTP session first, so SSE clients are no longer stuck behind zombie sessions for half an hour.

### ⚠️ Behaviour changes

- **MCP transport is either-or**: `server.transport` accepts only `http` (default) or `sse`; "serve both" is gone.
- Migration on upgrade: an explicit SSE choice is kept; everything else, including the old "both" default, becomes HTTP.
- Clients that only speak `/sse` must switch the transport to **SSE** in the MCP dialog after upgrading; clients that speak `/mcp` should stay on **HTTP**.

### 📦 Installation

- The installer is not code signed, so Windows SmartScreen may warn about an unknown publisher; this is expected for unsigned builds.
- Verification: see [code signing and installation](https://github.com/SeaHi-Mo/Seahi-Serial/blob/main/doc/SIGNING.md). Releases include `SHA256SUMS.txt` and a cosign keyless signature (`.sigstore.json`).
