This release rebuilds the quick commands column: a flat list with one loop switch becomes loop groups, the MCP actions are brought up to parity with the panel, and an old bug where a successful import was reported as a failure is fixed.

### ✨ New

**Loop groups: one table per group**

- A monitor can have several groups, each with a renameable header (drag handle, participation switch, name, collapse arrow, item count, delete). "New loop group" appends at the bottom with one empty command; a fresh install starts with one group, and the last group cannot be deleted.
- The loop order is the top-to-bottom order of groups, then the sequence number inside a group. Drag a group to the top and the loop starts there, wrapping after the last one. Reordering animates (FLIP) and is written back on drop.
- Each group has a participation switch: turning it off skips the whole group without touching any sequence number in the file.
- Each group carries its own header row (sequence, command, delay, HEX) with add at the far right, matching the file layout.
- Two blue markers: a sequence box with a value greater than zero is filled blue, meaning it takes part in the loop, and the collapse arrow is blue when the group is expanded.

**External files: one table per group, plus format documentation**

- In the file, a `## Group name` heading followed by a table is one loop group (two or more `#`; a single `#` is still a comment). Old files without headings are read as a single group and are not modified.
- New `doc/QUICK_CMDS.md` documents column names and aliases, group headings, comments and front matter, write-back rules, limits and FAQ.

**MCP: `serial_quick_cmd` completed**

- New `action` values: `loop` to turn looping on or off, `add`, `update` and `remove` for single commands, and `group` with add, remove, rename, move, on and fold.
- The listing is richer: every command reports its group and `domIds` that can be passed straight to `ui_set`, plus `groups[]` with participation and collapse state, and `loop{on, planLength}`.
- Every action reuses the same code path as the panel button rather than a separate implementation for AI.

### 🐛 Fixed

- **A successful import reported "import failed: TypeError ... (reading 'length')"**: after the group model landed, `quickCmds` became null while the success message still read its length, so the exception thrown inside `then` was caught and shown as a failure. The count now follows the group model, and an assertion forbids a failure message after a success.
- **Exports match the panel exactly**: the column order is sequence, command, delay, HEX (the sequence used to sit after the command), one row per panel entry including empty ones, no extra name column, and the HEX column written as a boolean.
- **Reordering groups had no animation** because the whole list was rebuilt on every move; only nodes are moved now, with a FLIP transition.
- **Collapsing a group left its header row behind**; the header now collapses with the rows.
- The minimum pane width goes from 120 to 300 px, matching the default, so a six-column row is no longer crushed in a narrow pane.
- Successful imports and reloads no longer show a notice, since the list itself is the feedback; failures still do.

### 🎨 Layout

- Group header order: drag handle, participation switch, name, collapse arrow next to the item count; add moved to the far right of the header row in the theme colour.
- The collapse arrow and drag handle are drawn in CSS instead of the `▾` and `⠿` glyphs, which were nearly invisible at small sizes.
- Horizontal separators are equal in length and start at the left edge of the panel, and header and data columns align pixel for pixel.
- The title row splits into two ends: the loop switch on the left for state, new group, import and export on the right for actions.
