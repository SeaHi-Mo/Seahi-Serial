This release brings Bluetooth (BLE) into AI control over MCP: instead of clicking generic interface controls one by one, an assistant can operate the panel in plain terms (33 tools became 49). It also fixes a class of problems where a tool existed but the client never received its arguments or saw its result, and makes WSL serial startup failures explain themselves.

### ✨ New

**Fifteen semantic BLE tools plus a danger list**

| Purpose | Tools |
|---|---|
| Scanning and listing | `ble_start_scan`, `ble_stop_scan`, `ble_list_devices` with `limit`/`offset` paging and `hasMore`/`nextOffset` |
| Connecting | `ble_connect` (clicks the card when the device is listed, connects by MAC when it is not, and uses the current selection when no MAC is given), `ble_disconnect` |
| Characteristics | `ble_get_services`, `ble_read`, `ble_write`, `ble_subscribe` |
| Data and signal | `ble_get_output`, `ble_refresh_rssi` |
| Peripheral role | `ble_periph_status`, `ble_periph_start`, `ble_periph_stop` |
| State | `ble_get_state`, which reports scan, connection and subscription state without touching the adapter |

- Every tool reuses the code path behind the panel button, so logs, icons and the write panel change with it.
- Dangerous actions need explicit confirmation: `ble_periph_start` and similar do nothing without `confirm:true` and return `-32006` explaining the consequence; `mcp_danger` lists them.
- Acting tools bring their panel to the front, while read-only state queries switch nothing, so a polling client does not yank the user away from another page.
- Scan results can be read three ways: the semantic tool, `ui_get_state` with `{"section":"bleDevices"}`, or the text summary, which prints one device per line with MAC, signal and paging offset.
- New self-check script `node .walkthrough/mcp_smoke.js` calls all 49 tools against the running application and prints the results, which immediately shows why a client cannot see a new tool: it is usually an old build, since tool definitions are compiled into the executable.

### 🐛 Fixed

- **The reply hop did not await a promise**: connecting, reading, writing and peripheral start return promises, but the reply read `res.ok` directly, so clients saw only "the interface failed" with no cause. The real reason now reaches the model.
- **`char` never reached the frontend for `ble_read` and `ble_subscribe`**: it was validated but not added to the payload, so both tools always answered "char required".
- **Scan results came from the panel cache**, refreshed every two seconds, so asking right after starting a scan returned an empty list; the backend is now queried on every call.
- **Scan results showed only a count** because the generic renderer expands three elements; the device table now prints one device per line and the generic array respects a character budget.
- **Subscription lookup was case sensitive**, so unsubscribing with the caller's UUID silently did nothing. The real UUID from the service tree is used instead.
- Characteristic icons are only in the DOM after expanding their service, which made AI report "unsupported characteristic"; the owning service is expanded first.
- `limit` and `offset` of `ui_get_state` were not forwarded, silently disabling paging over the generic bridge.
- WSL serial "bridge start timed out" now distinguishes a process that exited from a real timeout and includes the last lines of stderr plus hints about a missing python3, a script that did not reach /tmp, or a missing dialout group.
- The one-page cheat sheet marked dangerous write tools as read-only.
- Six `dead_code` warnings were cleared and `report::guard` is now actually used.

### 📚 Documentation

- `doc/MCP.md` gains two comparison tables: multiple entry points for the same data, and tools that look duplicated but are not.
- `doc/MCP_TOOLS.md` was regenerated with 49 tools, each with its return shape, limits and caveats.
- `AGENTS.md` documents which checks to run after changing MCP tools, including the smoke test against the running application.
