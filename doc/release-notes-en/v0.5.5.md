This release fixes an interface bug that could not be undone once triggered: after read-only (sandbox) mode was enabled, the switch in the dialog was permanently disabled, and that switch is the only way to turn read-only mode off. In read-only mode AI is refused even for `mcp_config_set`, which is intentional.

Users already stuck in read-only mode can install this version and click the button once, without editing `ai-config.json` by hand.

### 🐛 Fixed

- **Read-only mode could not be turned off.** `mcpToggleReadOnly()` disabled the button to prevent double clicks, and when the state came back `renderMcpStatus()` rewrote the label but never restored `disabled`, so after enabling read-only mode the button could never be clicked again. The disabled style only sets `opacity: .45`, which is almost invisible, so it looked like a dead button, and the only ways out were restarting the application or editing the configuration file. Disabling now depends on a separate in-flight flag `_mcpReadOnlyBusy`, and both the success and failure paths re-enable the button, so a backend hiccup cannot lock it.
- Seventeen assertions were added for this switch, including that it must be re-enabled after enabling read-only mode, that a second click really turns the mode off, and that a failed command also re-enables it. Run against the previous code, seven of the seventeen fail.

### 📚 Documentation

- `doc/MCP_DESIGN.md` §17 records the root cause and why the assertion set did not catch it: at the time only "the button exists" and "the label follows the state" were scanned, and nothing checked whether the button could still be clicked.
