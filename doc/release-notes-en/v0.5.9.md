This release turns quick commands from "send on a timer" into "send one and wait for its reply", with timeouts, retries and branch jumps. It also lets AI inspect and run automation workflows, closes a hole where dangerous buttons could be clicked through a generic tool, and splits the frontend from one 16,000-line `index.html` into 18 files, with no visible change.

### ⚠️ Behaviour change

**The delay column now means "how long to wait for a reply"**

- The old column name still works and is read as a timeout, with a one-time notice on import; exports now label the column as a timeout in milliseconds.
- The default is 3000 ms and the maximum 600000 ms; `0` means the command does not wait and the chain moves on immediately.
- The previous behaviour, sending at a fixed interval, is gone: the chain now always waits for the reply before continuing.

### ✨ New

**Quick commands: send one, wait for its reply**

- After sending, `busy` keeps waiting without deciding, `OK` moves to the next command, `ERROR` resends the same command up to three times, and exhausting the timeout or the retries terminates the chain.
- The judgement lives in one place, in Rust: the serial port feeds it from the read thread and WSL feeds it from the frontend, so the interface and AI see the same conclusion, and a late reply to the previous command is never credited to the next one.
- The loop switch state is still not persisted, and disconnect, closing the pane or running out of commands stops the loop with an explanation.

**Branch jumps: the command table can express a flow**

- Two more columns take effect only when the header declares them: success jump and failure jump. Empty means the next command, a number means jump to that sequence number, and "end" finishes the chain.
- A timeout also counts as failure, since a failing Wi-Fi setup usually times out rather than returning `ERROR`.
- More than 200 consecutive jumps stop the loop to prevent an infinite cycle, and a jump target that does not exist falls back to the next command with an explanation.
- No new controls were added to the panel: expectation and retry live in the file, shown by a soft outline and a tooltip on the timeout cell, and exports always include the columns.

**Automation workflows over MCP**

- New `serial_workflow` to read the rules and `serial_workflow_run` to run them, marked dangerous and requiring `confirm:true`.
- Actions performed by a matching rule are written to the `workflow` log channel, so AI can look back at what was sent automatically and when.

### 🔒 Security

- Dangerous buttons can no longer be clicked through a generic tool. Previously `ui_click` could press the start broadcast or run workflow button and bypass the explicit confirmation. Such controls now carry `data-mcp-skip`, invisible and unclickable to generic tools, and only the dedicated tools with `confirm:true` can trigger them.

### ♻️ Internal refactor

- The frontend split into `src/index.html` plus four CSS files and fourteen JavaScript files, loaded in order with plain `<link>` and `<script src>` tags sharing one global scope, with no bundler and no build step.
- The move is byte-exact: concatenating the files reproduces the original 900756 bytes and 15874 lines, and all 1730 frontend assertions pass unchanged along with 229 backend tests.
- The new `doc/FRONTEND_LAYOUT.md` records the directory layout, load order and what each file owns.
