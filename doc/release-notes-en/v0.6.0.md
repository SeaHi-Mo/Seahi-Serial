This release hands automation to an embedded Node-RED: flows are drawn on a canvas to receive data, decide, and send the next command, and a background engine runs them. The serial port is still owned by the application; nodes read and write through an internal bridge, so two programs never compete for the same COM port.

### ✨ New

**1. Embedded Node-RED editor**

- A new automation icon in the monitor toolbar opens the canvas below the monitor instead of a separate window.
- The editor is the full Node-RED distribution shipped with the installer (5.0.10), works offline and listens on the loopback interface only.
- Flows start running immediately after Deploy; closing the canvas does not stop them, only exiting the application does.
- Flows are stored in `%APPDATA%\com.seahi.seahi-serial\node-red\flows.json` and survive uninstall and upgrade.

**2. Four serial nodes**

| Node | Purpose |
|---|---|
| `serial rxd` | Receives port data in text, HEX or buffer form |
| `serial txd` | Sends data, with a configurable line ending in text mode |
| `serial request` | Sends one command, collects the reply and branches on several outputs by content |
| `cmd list` | Sends an entry from the quick commands panel |

- The port dropdown lists the ports that are currently open, shown as `COM3 · 115200`; a new node selects the first available port.
- `serial request` clears stale data before writing, so a reply cannot leak into the next round.
- `cmd list` stays in sync with the quick commands panel: editing a command there is picked up by deployed flows.

**3. Sent data appears in the serial monitor**

- Automation sends use the same path as manual sends and are visible in the monitor window; turning off message echo hides them.

**4. Other**

- A help button in the title bar opens the online documentation.
- A new Node-RED automation guide covering node options, scheduled sends, receive branching and caveats.

### 🔧 Fixed

**1. False timeouts when reading WSL status**

- The "get_wsl_distributions timed out" message on the WSL panel is fixed. The backend probed each distribution in turn, which could take well over ten seconds while the frontend waited only six. The backend now has an overall probe budget, the frontend waits twelve seconds and retries once after a timeout.

**2. Removed automation nodes came back**

- Nodes removed from the package lingered in the user directory and kept showing in the palette. Delivery now clears node files that no longer exist, and development builds read resources straight from the repository.

**3. Bridge replies lacked the request id**

- Failed replies from the internal bridge carried no request identifier, so calls waited until they timed out without showing the real reason.

**4. Wording when a port is not open**

- The internal concept "monitor main has no open port" is gone. A closed port now reports `COM17 not open`, and a machine with no open port reports `no serial port available`.

### ⚠️ Behaviour changes

**1. The quick command "wait for reply, expect, retry, jump" DSL is disabled**

- Looping sends are unaffected and still follow sequence numbers and the timeout pacing.
- The expect, retry and jump columns in command files are still parsed and written back, so existing files are not damaged.
- The panel no longer shows hints for them, and passing those parameters through MCP now returns an explicit parameter error instead of being ignored.
- Use the `serial request` node when a command must be confirmed by its reply.

**2. Automation nodes were renamed**

- `serial in` became `serial rxd` and `serial out` became `serial txd`.
- Flows using the old names show unknown nodes and must be rewired; the old names were never part of a public release.

**3. The installer grows by about 172 MB**

- The Node-RED runtime (node.exe and its dependency tree, about 9,600 files) ships with the installer, which is the cost of working offline.

### 📦 Installation

- The installer is not code signed, so Windows SmartScreen may warn about an unknown publisher; this is expected for unsigned builds.
- Verification: see [code signing and installation](https://github.com/SeaHi-Mo/Seahi-Serial/blob/main/doc/SIGNING.md). Releases include `SHA256SUMS.txt` and a cosign keyless signature (`.sigstore.json`).
