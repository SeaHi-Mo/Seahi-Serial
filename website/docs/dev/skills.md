# 技能（skills）

仓库根目录的 `skills/` 不是给最终用户的，是**写给 AI 助手的开发手册**：项目约束、常用命令、已经踩过的坑。

改代码前先让助手读一遍对应技能，比在对话里反复解释省事得多，也能避免它「重新发明」一套和项目约定冲突的做法。

## 怎么用

技能就是普通的 Markdown 文件，没有安装步骤。三种用法：

**1. 直接让助手读文件**（最通用）

> 先读 `skills/seahi-serial-dev/SKILL.md`，再改 `src/js/10-monitor.js`。

**2. 支持技能目录的客户端**

Claude Code / Cline 等支持自定义指令或规则，把 `skills/` 指过去即可；DeepSeek Harness 里可以直接 `@skills/seahi-serial-dev/SKILL.md` 引用文件。

**3. 作为项目规则常驻**

把技能里的「必须遵守的约束」抄进 `AGENTS.md` 或客户端的自定义指令，让助手每轮都带着这些约束工作。

## 现有技能

### `seahi-serial-dev`

**什么时候用**：任何要改前端、后端、MCP 的开发任务。

里面写了：

- 项目概况与目录（前端无构建步骤、共享全局作用域）；
- 常用命令与测试要求（改前端跑断言集、改 MCP 跑 `mcp_smoke.js`）；
- **必须遵守的约束**：版本号五处同步、MCP 传输与会话规则、日志旁路不许阻塞、`config.json` 里不能出现 AI 痕迹等；
- 常见陷阱与排查路径。

### `win-build-access-denied`

**什么时候用**：`npm run dev` 跑完没有窗口、`cargo build` 报「拒绝访问 / OS Error 5」、构建脚本读不到 `tauri.conf.json`。

**先确认是不是编译就失败了，再去怀疑应用逻辑**——大多数「跑了命令没窗口」都是构建阶段挂掉，错误混在一屏日志里被当成「还在编译」。

技能里给了决策流程、典型错误对照和修复命令，覆盖 NTFS 低完整性标签与目录权限污染这两类环境问题。

## 推荐流程

1. 读 `AGENTS.md`（项目约定总表）；
2. 按任务挑技能：日常开发 → `seahi-serial-dev`；构建报错 → `win-build-access-denied`；
3. 动手改；
4. 跑测试：后端单测 + 前端断言集（改 MCP 再加 `mcp_smoke.js`）；
5. 涉及版本号 / 发版时，按 `AGENTS.md` 的「版本号同步」检查。

## 写新技能

新增技能时：

- 目录名用小写连字符，`skills/<name>/SKILL.md`；
- 开头写清「什么时候用」——这句决定助手会不会在正确的时机读到它；
- 只写**能执行的规则**（命令、判据、禁止事项），少写背景介绍；
- 和 `AGENTS.md` 冲突时以 `AGENTS.md` 为准，并在技能里说明这一点。
