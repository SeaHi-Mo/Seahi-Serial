# ADB 调试

ADB 面板用来调试 Android 设备，不占本机 COM 口。它通过安装包自带的 `platform-tools` 里的 adb 命令与设备通信：列设备、开一个交互式 shell、在 shell 里敲命令。

## 打开面板

点标题栏的 ADB 图标进入。进入后这个图标变成「返回到串口调试器」，再点一次回串口页；点标题栏左侧的应用图标也能回去。

面板分两块：

- 顶部是设备栏，横向排列设备卡片，右端是「刷新」按钮。
- 下方是会话区，没有会话时显示「选择上方设备开始调试会话」。

面板内容在第一次打开时创建，之后切走再回来复用同一份界面，不会重建；每次回来都会刷新设备列表，并把后台会话的输出轮询恢复到 120ms。

ADB 页打开期间，标题栏的「打开额外监视器」会被置灰，提示「ADB 界面不可用」。

## 使用流程

1. 用 USB 线连接 Android 设备，在开发者选项里打开 USB 调试。
2. 点标题栏的 ADB 图标进入面板，设备列表会自动刷新一次。
3. 在设备上允许这台电脑的 USB 调试，卡片状态从 `unauthorized` 变成 `device`。
4. 点状态为 `device` 的卡片，等会话区出现终端提示符。
5. 在终端里敲命令，输出直接画在同一个画布上。
6. 换设备就点另一张卡片，当前会话会先被关闭回收。
7. 点标题栏的 ADB 图标或应用图标回串口页；后台会话保留，输出轮询降频。

## 设备列表

进入面板会立刻刷新设备列表；面板开着时每 5 秒自动刷新一次，因为 ADB 设备不在串口插拔通知的范围内。也可以点「刷新」手动取一次。

每张卡片显示设备型号（没有型号时显示序列号）和一个状态点。点卡片打开这台设备的会话：

- 再点同一台，只是把焦点交回已有终端，不会重复连接。
- 点另一台，会先关闭并回收当前会话，再为新设备建终端（同一时间只保留一个 ADB 会话）。

状态点按 `adb devices -l` 返回的状态着色：

| 状态 | 颜色 | 含义 |
|---|---|---|
| `device` | 绿 | 可用 |
| `unauthorized` | 红 | 设备还没允许 USB 调试，需要在设备上点「允许」 |
| `offline` | 橙 | 设备没响应，重新插拔或重启 adb 服务后再试 |
| `no` / `no-permissions` | 红 | 无权限访问该设备 |
| `recovery` / `sideload` / `bootloader` / `connecting` / `authorizing` | 橙 | 设备处于过渡状态 |
| `error` / `failed` / `unknown` | 红 | 读取状态失败 |

列表为空时显示「未检测到 ADB 设备」；adb 找不到时提示检查 adb 是否已安装。

## 打开 shell

点设备卡片后，会话区会新建一个 xterm 终端，后端在伪终端（PTY）里执行 `adb -s <序列号> shell`：

- 环境变量 `TERM=xterm-256color`、`COLORTERM=truecolor`，工作目录 `C:\`。
- PTY 先按 40 行 × 120 列打开，等 1.5 秒让 shell 起来，再开始读输出。
- 前端拿到 PTY 会话 id 后把焦点交给终端，之后所有按键都写进这个 PTY。

打开失败时终端里会留一行红字「连接设备失败: …」，失败原因不会只藏在控制台里。

终端回滚缓冲保留最近 1000 行，配色固定为深色，不跟随界面主题。

关闭会话的方式是切到另一台设备：旧会话的子进程会被结束、终端实例会被收掉、PTY 会话从后端移除。离开 ADB 页面不会关闭后台会话，只会把输出轮询从 120ms 降到 2000ms；切回来会恢复。

## 输入与输出

- 直接在终端里敲键，按键原样写进 PTY，由设备上的 shell 解释。ADB 面板没有发送输入框、行缓冲和发送历史，回车由终端发出 `CR`。
- 输出由前端每 120ms 轮询一次并交给 xterm 解析，ANSI 颜色、光标移动和全屏程序都按终端处理；新输出自动滚到底。
- 页面隐藏时轮询降到 2000ms，避免离开面板后还高频空转后端。
- 前端取走不及时时，后端 PTY 的输出队列上限是 512 块，超出会丢掉最旧的块并计数；终端里会打印一行黄色提示「已丢弃 N 块输出」，不会假装数据是完整的。
- 终端尺寸由前端按容器实际像素计算列数和行数，再调 `adb_shell_resize` 同步给后端 PTY。面板隐藏时容器尺寸为 0，这一轮不量、不同步，避免把 shell 缩成 2×2 压碎缓冲区。
- 粘贴内容也走同一条写入命令，原样送进 PTY；多行内容一次写入，由设备上的 shell 自己解析。

## 终端里的操作

- 键盘输入原样写进 PTY：Tab 交给设备 shell 做补全，方向键、Ctrl 组合键和全屏程序的按键都不在本机拦截。
- 终端不维护命令历史，历史由设备侧 shell（readline）负责，`↑` 取到的是设备自己记的那一条。
- 画布可以用滚轮翻看最近 1000 行；有新输出时自动回到底部。
- 终端没有「复制全部」「保存日志」按钮，内容只存在终端缓冲里，关闭程序后不保留。

## 与串口终端的区别

| 项目 | ADB 终端 | 串口分栏的终端模式 |
|---|---|---|
| 输入口径 | 按键原样写进 PTY | 直发 / 行缓冲两种 |
| 回滚行数 | 1000 行 | 5000 行 |
| 配色 | 固定深色 | 跟随当前主题 |
| 输出轮询 | 可见 120ms、隐藏 2000ms | 可见 25ms、隐藏 500ms |
| 关闭会话 | 点另一台设备时回收 | 关闭分栏时销毁实例 |
| 会话缓存 | 不写 log-cache 缓存文件 | 写入 log-cache |

## adb 工具

程序按这个顺序找 `adb.exe`：

1. 程序目录下的 `platform-tools\adb.exe`。安装包会把 `platform-tools` 分发到这里。
2. 从程序所在目录逐级向上找 `platform-tools\adb.exe`，用于开发目录里直接运行构建产物的场景。
3. 系统 `PATH` 里的 `adb.exe`。

三处都没有时，设备列表会提示「请检查 adb 是否已安装」。安装时可勾选「将 ADB 工具(platform-tools)添加至系统 PATH」，之后在终端或脚本里也能直接用 `adb`。

程序没有单独的 adb server 启停按钮：`adb devices`、`adb shell` 这些命令第一次运行时，adb 会自己把常驻的服务进程拉起来。安装和卸载时，安装器会先结束镜像路径位于本应用 `platform-tools` 下的 adb，避免它锁住文件导致升级失败；Android Studio 或其它来源的 adb 不受影响。

常见的提示与处理：

| 提示 | 原因 | 处理 |
|---|---|---|
| `未找到 adb 可执行文件` | 三处查找都没有 adb | 重新安装，或把 platform-tools 加进 PATH |
| `adb devices 执行超时` | adb 命令 5 秒内没返回 | adb server 卡住或设备无响应，重启 adb 服务后再刷新 |
| `未检测到 ADB 设备` | 列表为空，或 adb 不可用 | 检查 USB 线、USB 调试是否打开、是否已在设备上授权 |
| `unauthorized` | 设备还没允许这台电脑调试 | 在 Android 设备上允许 USB 调试 |
| `offline` | 设备没响应 | 重新插拔设备，或重启 adb 服务后再刷新 |
| 终端里 `连接设备失败: …` | `adb shell` 没建起来 | 按红字里的原因处理，通常是设备断开或未授权 |
| 终端里 `已丢弃 N 块输出` | 前端取走不及时 | 关掉刷屏的后台命令，或换一台输出少的设备 |

## 说明

- 面板只提供设备列表和交互式 shell；文件传输、日志抓取这类操作不在面板里。
- 同一时间只维护一个会话。切换设备时旧 shell 会被结束，不会在后台留着多个 PTY。
- 终端配色固定深色，与串口分栏的终端模式不同，ADB 终端不跟随主题。
- 找 adb 时不读取 `ANDROID_HOME` 之类的环境变量，只看上面列出的三处路径。
- 设备列表的 5 秒自动刷新只在 ADB 页打开期间运行，离开页面就停止。
