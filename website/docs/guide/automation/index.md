# Node-RED 自动化

程序内嵌了 Node-RED 编辑器，用画布编排串口的收发流程：收到某段数据后判断、再自动发出下一条指令，或按固定节奏循环发送。

编辑器是随程序分发的完整 Node-RED，画布保存为流程文件，部署后由后台引擎执行。流程适合承担固定的收发顺序、应答判断和定时任务。

这个分组包含四页：

- 本页：打开画布、修改节点属性、部署与运行
- [快速开始](/guide/automation/quick-start)：导入一条最小流程并发送第一条指令
- [节点说明](/guide/automation/nodes)：四个串口节点的作用、属性设置与常见用途
- [常用流程](/guide/automation/flows)：从空白画布完成定时发送、请求应答和接收分支

## 打开编辑器

点击顶部工具栏的 Node-RED 图标，程序打开独立的编辑器窗口。编辑器独立于分栏存在，一套流程服务所有分栏，因此窗口不会随面板切换而关闭。窗口与主窗口并列摆放，可一边查看串口数据一边修改流程；窗口大小与位置由程序记住，再次点击图标只是把已打开的窗口切到前面，不会打开第二个编辑器。

使用前需要先在串口面板打开端口。自动化节点不自行打开串口，端口由程序独占，节点通过内部通道读取和写入。

关闭编辑器窗口不影响流程运行，只有退出程序才会停止。

## 打开节点属性

节点参数都在属性面板中设置：

1. 在画布上双击节点，右侧打开属性面板。
2. 在面板中修改名称、端口、格式、超时等参数。
3. 点击面板右上角的「完成」保存到画布；点击「取消」放弃本次修改。
4. 参数修改后点击画布右上角的「部署」，流程才会按新参数运行。

属性面板只修改当前节点。画布上的修改在部署前只存在于编辑器中，不会写入流程文件。

## 部署与运行

<GuideMedia
  poster="/img/guide/automation-deploy.png"
/>

| 项目 | 说明 |
|---|---|
| 生效时机 | 点击「部署」后立即运行；未部署的修改只在编辑器中可见 |
| 运行位置 | 后台引擎，关闭编辑器窗口后继续运行 |
| 停止时机 | 退出程序 |
| 流程文件 | `%APPDATA%\com.seahi.seahi-serial\node-red\flows.json` |

卸载程序不会删除该目录，升级后流程保留。删除流程页签或修改连线后，需要点击「部署」才会写入流程文件。未部署的修改只存在于编辑器窗口内，关闭窗口后丢弃，与浏览器里的编辑器行为一致。

## 注意事项

- 端口由程序独占。自动化节点与其他串口功能共用同一个端口，不需要也不能自行打开。
- 同一端口上只放置一个 `serial rxd` 或 `serial request`。内部接收队列由两者共用，多个节点会互相分走数据块；需要在多处使用时，接一个节点后再向下游分叉。
- 行尾必须与设备要求一致。设备不识别换行时不会应答，表现为只发不收。
- 设备开启回显（`ATE1`）时，发出的指令会被原样返回，可能提前命中 `serial request` 的结果分支。建议先发送 `ATE0` 关闭回显。
- 接收使用轮询方式获取数据，默认间隔 100 毫秒，接收延迟处于该量级。
- 流程中引用的节点类型被移除或改名后，画布上会显示为未知节点，需要重新拖入并连线。
