# serial request

## 作用

承担一次完整的请求与应答事务，顺序固定为三步：清空此前残留的接收数据、写入命令、收集回复窗口。窗口在命中结果分支、连续静默或达到最长等待时结束，然后按命中的分支输出。

## 属性设置

双击画布上的节点打开属性面板。

| 参数 | 设置方法 |
|---|---|
| 名称 | 画布上显示的文字，只影响可读性；留空显示 `serial request` |
| 端口 | 下拉选择当前已打开的串口 |
| 发送格式 | `文本` 或 `HEX`；发送为 HEX 时不追加行尾 |
| 回复格式 | `文本` / `HEX` / `Buffer`；决定输出 `payload` 的类型 |
| 行尾 | 文本发送时追加 `CRLF` / `CR` / `LF` / 不加 |
| 最长 ms | 从发出命令开始的总等待上限，默认 1000 |
| 静默 ms | 收到字节后连续无新数据达到该时长即收口，默认 80 |
| 结果分支 | 每行一个条件，命中后从对应连接点输出；默认包含 `OK` 与 `ERROR` |

结果分支支持「包含」「等于」「正则」和「未匹配或超时」。条件按从上到下的顺序匹配，第一个命中的分支生效；「未匹配或超时」是兜底条件，只有前面都没有命中时才走它。

未配置兜底条件时，没有命中的应答会被丢弃，节点状态标黄并给出提示，不会当作成功。

## 输出内容

命中分支后输出一条消息，除 `payload` 外还带以下字段。

| 字段 | 含义 |
|---|---|
| `raw` | 收到的原始字节 |
| `cmd` | 本次发送的文本 |
| `bytes` | 收到的字节数 |
| `elapsedMs` | 从发送到收口经过的时间 |
| `matched` / `matchedIndex` / `matchedType` | 命中的条件内容、序号与类型 |
| `timedOut` | 是否因达到最长等待而结束 |
| `reason` | 结束原因：`rule` / `timeout` / `quiet` |

## 常见用途

| 场景 | 做法 |
|---|---|
| 判定指令是否成功 | 把 `OK` 与 `ERROR` 接到不同分支，分别处理后续步骤 |
| 上电自检 | 复位后先发 `AT`，等到 `OK` 再继续初始化 |
| 异常时的补偿 | 命中 `ERROR` 分支后接 `delay` 与重发，形成有限次重试 |

同一节点内的请求串行排队，上限 32 条，两段回复不会串到下一轮。

## 注意

设备开启回显（`ATE1`）时，发出的指令会被原样返回，可能提前命中条件。使用前先发送 `ATE0` 关闭回显。

节点自己读取接收队列，同一端口上不要再放 `serial rxd`，两者会互相分走数据块。
