# 蓝牙调试（主机方向）

顶栏切到蓝牙面板，点「开始扫描」搜索周边 BLE 设备。列表里能看到名称、MAC、RSSI、设备类型，以及 iBeacon / Mesh 标记。

## 扫描与连接

- 点设备卡片连接；连上后右侧展开 **GATT 服务树**。
- **连上设备会同步停止扫描**——不用再手动点「停止」。
- 连着设备时仍可以再扫描（找下一台是正常需求），但新连接也会同样停掉扫描。
- 每次扫描有时长上限，到点自动停；停扫描只有一个出口，界面不会出现「按钮写着开始、后台还在刷列表」。

## 设备不在列表里也能连

被 Windows 配对过、或被别的主机连走的设备**往往不再广播**，于是永远进不了扫描列表。这类设备用 **按 MAC 直连**：直接 `connect`，不依赖广播。

## 服务树里看到的是什么

服务与特征显示的是**官方名称**，来自 Bluetooth SIG 的 UUID 表（内置 78 个服务 + 512 个特征）。表里没有的会标成 `Custom Service` —— 不猜、不硬套。

可以：读取特征 / 写特征与描述符 / 订阅通知与指示。原始字节按 HEX 显示，文本类特征会给出可读内容。

## CTS：时间直接翻成人话

认得出 **Current Time Service**：

| 特征 | 内容 |
|---|---|
| `0x2A2B` | 当前时间 |
| `0x2A0F` | 时区与夏令时 |
| `0x2A14` | 时间源 / 精度 / 距上次对时 |

读到或收到这些字节时，数据日志里会紧跟原始 HEX 补一行人话，例如：

```
→ 2026-12-17T15:45:58.500Z（周四） · 设备时钟比本机快 …
```

订阅之后能直接看着设备时钟走。

::: tip 三态要分清
「设备没给」和「值就是 0」是两件事。未给出、超量程、保留值一律显示为「未给出」，不会拿 `0` 冒充「不知道」。
:::

## 设备名：只认广播名

Windows 在连上之后会把系统缓存的名字盖到设备上，那个名字**可能是设备从来没叫过的**（例如一个被误识别的型号串）。所以界面展示名一律取**广播里的名字**，系统名只在设备完全没广播名字时兜底。

想知道设备自称什么，读 `0x1800` 服务下的 `0x2A00`（Device Name）——那是权威值。

## 配对

需要绑定的设备走 WinRT 配对。配对过程中 Windows 会弹出系统确认框，**必须由你在系统弹框上点确认**——程序不能替点，这段时间请勿关闭窗口。

## 从机（外设）方向？

已移除。适配器自称支持外设角色，实测广播起不来，整条功能下线，避免留一个「看着能用、实际不通」的入口。BLE 只剩主机方向。
