# 错误上报

程序会收集运行时发生的错误，发送到作者自建的错误收集服务，用来定位和修复问题。这一页说明上报什么、什么时候上报、数据去哪里，以及怎么关闭。

## 上报什么

发生这三类错误时会上报：

- 程序崩溃（panic）：任何线程的 panic 都会被捕获。
- 后端运行期错误：串口打开、读写、DTR/RTS，蓝牙连接与读写，ADB 会话，WSL 映射，更新检查等操作失败。
- 前端脚本异常：未捕获的 JS 错误、未处理的 Promise 拒绝，以及界面上已经提示过的错误。

每次上报包含这些字段：

| 字段 | 内容 |
|---|---|
| 应用版本 | 例如 `0.5.23` |
| 操作系统 | 例如 `windows` |
| 错误信息 | 错误文本，过长会截断 |
| 堆栈 | 出错位置；前端带调用栈，后端带文件与行号 |
| 上下文标签 | 出错的功能，例如 `send_data`、`open_wsl_serial`、`connectPort` |

**不会**上报串口收发内容、日志正文、设备数据或配置文件内容。堆栈里可能出现源码文件路径，用于定位问题，但不含设备交互内容。

## 什么时候上报

错误产生时先入队，由后台线程发送，不阻塞串口收发。同一类错误（上下文 + 错误首行）在 5 分钟内只上报一次，避免刷屏；被合并的次数会写进本地日志。

上报失败（网络不通、服务端拒绝）只在本地日志留一行 `[report] 上报失败（上下文）`，不弹窗，也不影响正常使用。

## 数据去哪里

发送到作者自建的错误收集服务（Cloudflare Workers + D1），不经过任何第三方错误平台。服务端按「错误 + 堆栈」分组，每组只保留最近 100 条明细。

## 关闭上报

启动程序前设置环境变量 `SEAHI_ERROR_REPORT=0`：

- 临时关闭（PowerShell，只对当前会话生效）：先执行 `$env:SEAHI_ERROR_REPORT="0"`，再启动程序。
- 长期关闭：`Win + R` 输入 `sysdm.cpl` 打开系统属性，进入「高级」→「环境变量」，新建用户变量 `SEAHI_ERROR_REPORT`，值为 `0`，然后重新登录或重启程序。

`false` 和 `off` 与 `0` 同义。

## 本地日志

即使关闭上报或上报失败，错误仍会写进本地调试日志 `%TEMP%\seahi-serial-debug.log`（超过 4 MB 自动轮转，保留一份 `.1`）。在 `Win + R` 里输入 `%TEMP%` 可以打开所在目录。

MCP 的日志中心另有独立的 `error` 通道，AI 客户端可以用 `log_tail` 读取。
