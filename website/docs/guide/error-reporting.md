# 错误上报

程序会收集运行时错误并发送至作者自建的错误收集服务，用于问题定位与修复。本页说明上报内容、上报时机、数据去向与关闭方式。

## 上报内容

上报分为以下三类：

- 程序崩溃（panic）：任何线程的 panic 均会被捕获。
- 后端运行期错误：串口打开、读写、DTR/RTS，蓝牙连接与读写，ADB 会话，WSL 映射，更新检查等操作失败。
- 前端脚本异常：未捕获的 JS 错误、未处理的 Promise 拒绝，以及界面已提示的错误。

每次上报包含以下字段：

| 字段 | 内容 |
|---|---|
| 应用版本 | 例如 `0.5.23` |
| 操作系统 | 例如 `windows` |
| 错误信息 | 错误文本，过长时截断 |
| 堆栈 | 出错位置；前端包含调用栈，后端包含文件与行号 |
| 上下文标签 | 出错功能，例如 `send_data`、`open_wsl_serial`、`connectPort` |

串口收发内容、日志正文、设备数据与配置文件内容不会上报。堆栈可能包含源码文件路径，用于定位问题，不包含设备交互内容。

## 上报时机

错误产生后先入队，由后台线程发送，不阻塞串口收发。同一类错误（上下文与错误首行）在 5 分钟内仅上报一次，以限制重复上报；被合并的次数写入本地日志。

上报失败（网络不可用或服务端拒绝）时，仅在本地日志写入一行 `[report] 上报失败（上下文）`，不显示弹窗，也不影响正常使用。

## 数据去向

数据发送至作者自建的错误收集服务（Cloudflare Workers + D1），不经过第三方错误平台。服务端按错误与堆栈分组，每组保留最近 100 条明细。

## 关闭上报

启动程序前设置环境变量 `SEAHI_ERROR_REPORT=0`：

1. 临时关闭：在 PowerShell 中执行 `$env:SEAHI_ERROR_REPORT="0"`，然后启动程序。该设置仅对当前会话生效。
2. 长期关闭：在 `Win + R` 中执行 `sysdm.cpl` 打开系统属性，依次进入「高级」与「环境变量」，新建用户变量 `SEAHI_ERROR_REPORT`，值为 `0`，然后重新登录或重启程序。

`false` 和 `off` 与 `0` 等价。

## 本地日志

关闭上报或上报失败时，错误仍会写入本地调试日志 `%TEMP%\seahi-serial-debug.log`（超过 4 MB 自动轮转，保留一份 `.1`）。在 `Win + R` 中输入 `%TEMP%` 可打开所在目录。

MCP 日志中心另设独立的 `error` 通道，AI 客户端可通过 `log_tail` 读取。
