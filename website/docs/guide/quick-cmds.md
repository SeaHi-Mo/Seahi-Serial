# 快速指令

快速指令面板位于输出区右侧，默认折叠。点击可展开，向左拖动折叠条可调整宽度：最小 300px，最大不超过窗格的 60%，并始终为输出区保留 160px。该面板用于执行一组需要交互的指令，例如配网、校准或批量写入参数。

标题栏左侧为「循环发送」开关，右侧为「＋ 新建循环组」「导入」和「导出」。导入文件后，标题下方显示来源行，包括文件名、「重载」和「断开」。未关联文件时，列表保存在本机配置中；关联文件后，以文件作为存储，配置中保留缓存，文件无法读取时使用缓存。

## 分组

指令按循环组管理。每组为一张独立表格，包含组抬头、列标题和数据行，与文件中「一组一张表」的结构一致。

- 点击组名可直接修改。关联文件时，该操作同步改写文件中的 `## 组名`；旧文件没有组抬头时仅修改面板，不会向文件添加抬头。
- 按住抬头左侧的点阵握柄上下拖动可调整组顺序。最上面的组为循环起点，文件中的表格顺序随之改变。
- 折叠箭头仅收起显示，不影响循环发送。
- 抬头上的滑动开关控制该组是否参与循环发送。关闭后整组跳过，顺序号保持不变，重新打开即可恢复。开关与折叠状态保存在本机配置中；外部文件没有组级开关列。
- 抬头显示该组指令数量；最右侧的 × 删除整组及组内指令。仅剩一组时删除操作会被拒绝，可删除组内指令。
- 列标题最右侧的「＋ 添加」在组末尾追加一条空指令。新建组追加到末尾，默认名称为「循环 N」，包含一条空指令；关联文件时，会在文件末尾补充该组的抬头、表头和该条数据行。

## 指令字段

| 字段 | 说明 |
|---|---|
| 顺序号 | 最多 4 位数字。`0` 表示不参与循环；大于 `0` 的条目在组内按数字升序发送，同号按行序处理 |
| 指令 | 原样发送；`\r\n`、`\t` 等转义序列会生效；在输入框中按回车等同于点击该条目的发送按钮 |
| 超时(ms) | 该条目占用的时间，默认 3000，上限 600000（10 分钟）；具体含义见下节 |
| HEX | 该条目按十六进制解析后发送，与主发送栏当前的文本/HEX 模式无关 |
| 发送 / 删除 | 单独发送该条目（未连接时不可用），或删除该条目 |

面板不提供名称入口：文件中的名称列会原样保留，导出副本不包含该列。期望、重试、成功跳转和失败跳转仅在文件中配置。存在这些配置时，超时单元格显示淡色边框，悬停可查看内容；导入时也会给出一次提示。

## 超时与「期望」

「超时」的解析方式取决于「期望」是否为空：

- 「期望」非空且超时大于 0 时，超时为发送后等待回话的上限。收到成功词后提前进入下一条，等待超时后进入失败分支。
- 「期望」为空时，条目不校验回话，超时即下一条发送前的间隔。例如填 3000 表示每 3 秒发送一条。
- 超时填 0 时，条目不等回话（即使设置了「期望」），按 20ms 的最小间隔连续发送。
- 清空超时输入框会恢复默认值 3000，不会变为 0。

仅当文件表头声明「期望」列且单元格非空时，条目才会等待回话。无成功词时缺少成功判定依据，内置 OK 也不会作为默认判定。需要等待内置 OK 时，在「期望」列写入 `OK`。

## 回话判定

回话由后端按行判定，前端负责发送、等待并按结论进入下一步。

- 回话需包含换行符（`\r` 或 `\n`）才会切分为行。跨读取块的半行会拼接；始终没有行尾的数据会等待至超时。
- 行内含 `busy`：继续等待，不产生结论、不重发，也不延长超时。
- 行内含 `error`：判定为失败并重发该条目。同时含 `busy` 的行按 busy 处理，继续等待。
- 整行为 `OK`，或以 ` OK` 结尾（例如 `SEND OK`）：判定为成功。
- 整行等于「期望」中的任一成功词：判定为成功。多个成功词用 `|` 分隔，例如 `WIFI GOT IP|OK`。比较时去除首尾空白并忽略大小写，采用整行相等判定，不支持包含匹配。
- 无法识别的行不产生结论，继续等待。

在等待回话的条目上，内置的 `OK`、`error` 和 `busy` 始终生效；「期望」在其基础上追加成功词，不能停用内置判定。因此无法实现仅接受 `WIFI GOT IP` 而拒绝 `OK`。需要包含匹配或正则匹配时，使用工作流规则（更多设置 → 工作流；条件类型包括字符串包含、正则表达式和精确字节）。

收到 ERROR 后，间隔 300ms 重发。默认重发 3 次（最多尝试 4 次），上限 10，`0` 表示不重发。等待超时同样判定为失败。失败后进入失败跳转；未配置失败跳转时终止整条链。终止弹窗会说明所属组、条目及等待时长；重试次数用尽时显示「连续 N 次收到 ERROR」。

前端每 60ms 查询一次后端结论。后端在查询时结算超时，前端额外保留 400ms 宽限，避免提前判定。

## 循环发送

启动前检查两项条件：监视器已连接；参与循环的组中至少存在一条顺序号大于 0 的指令。任一条件不满足时，启动会被拒绝并给出原因，不会出现开关已开启但未发送的情况。

- 循环顺序为组从上到下、组内顺序号升序；最后一组完成后回到最上面的组。顺序号 `0` 跳过，不占用位置。
- 每一步都会重新获取执行计划。循环运行期间修改顺序号、拖动组、增删条目或修改超时、期望、跳转，均在下一步生效，无需重新启动。
- 成功跳转在收到成功词后执行；失败跳转在超时或 ERROR 重试用尽后执行。留空或「下一条」表示顺序执行，数字表示跳转到对应顺序号（可跨组），「结束」表示停止。失败跳转留空时默认终止整条链。
- 不支持「下一组」跳转，跨组跳转通过顺序号实现。跳转按顺序号查找；不同组使用相同顺序号时，定位到执行计划中先出现的条目。
- 目标顺序号不存在时，导入阶段提示一次；实际执行到该步骤时，成功跳转按「下一条」处理，失败跳转按「终止」处理，原因写入控制台。
- 跳转列中无法识别的取值按「下一条」处理，导入阶段提示一次。
- 连续跳转超过 200 次时自动停止（中间执行一次顺序步骤即清零），用于阻止在少数条目之间反复循环。

### 条目发送与失败处理

点击条目发送按钮，或在指令输入框中按回车，仅发送该条目，不启动循环，也不等待回话。该操作与循环发送共用发送路径：由条目的 HEX 开关决定文本或十六进制发送；文本按面板行尾设置追加行尾，HEX 不追加；内容为空时不发送。手动发送失败时，输出区写入一行错误信息。

循环发送对以下情况分别处理：

- 条目内容为空：跳过该条并继续。连续跳过的数量达到一整轮的条目数时，说明整条链均无内容可发送，循环停止并提示。
- 连接已断开、设备写入失败或 HEX 内容格式非法：发送失败，整条链立即停止，不会跳转至其他条目。
- 正常收尾（成功跳转设为「结束」）：静默停止，不显示提示。

循环运行期间，输出区不写入循环状态信息，包括已发出、收到 OK、busy、重发、跳转、正常收尾和跳过。可见状态仅为面板上的「循环发送」开关和折叠条上闪烁的状态点；条目是否等待回话，可通过超时单元格的悬停说明确认。

循环在以下情况自动停止：连接断开（包括 WSL 读轮询连续 3 次失败）、发送失败（连接断开、设备写入报错、HEX 格式非法）、整轮无内容可发送、没有顺序号大于 0 的条目、跳转死循环、ERROR 重试用尽、等待超时。停止时显示一次弹窗，弹窗包含停止原因，异常详情写入控制台。手动关闭开关不显示提示；关闭监视器会终止相关定时器。

「循环发送」开关状态不保存，程序启动后不会自动开始发送；快速指令分栏每次打开也保持折叠状态。

## 关联外部文件

「导入」打开原生文件选择框，选择文件后该分栏的增删改都会写回文件（去抖 600ms），文件作为存储。可选择的扩展名包括 md、markdown、txt、tsv 和 csv；格式由内容判断，与扩展名无关。

- 仅接受在原生文件选择框中选择过的路径。后端维护允许列表（最近 50 个），前端传入任意路径会被拒绝。
- 同一文件不能被两个监视器同时关联。导入时第二次关联会被拒绝，并提示先在对应分栏执行「断开」；从配置恢复时若发现重复，后一个分栏的文件关联不再恢复（列表仍从配置缓存恢复）并提示一次。
- 来源行的「重载」会重新读取文件。重载失败时保留当前列表并提示，不会清空；下次启动会自动重新读取，读取失败时使用配置中的缓存。
- 关闭窗口前，仍处于 600ms 去抖等待中的写回会立即执行。

### 文件格式

`## 组名` 抬头用于分隔循环组（两个及以上 `#`）；单个 `#` 与 `//` 开头仍为注释；注释、空行和表头按原位置保留。没有抬头的旧文件读取为一组：读取时不添加抬头，写回也不改变表结构。载体由内容自动识别（出现 `##` 抬头时按 Markdown 处理），写回沿用识别结果：

| 载体 | 形式 |
|---|---|
| Markdown 表格 | 含 `\|`，推荐；列与分组通过表头和 `##` 抬头表达 |
| TSV | 使用制表符分隔，例如从 Excel 直接粘贴 |
| 纯指令行 | 一行一条指令 |

换行统一写为 CRLF。解析不按逗号切分：`AT+CWJAP="ssid","pwd"` 作为一次完整发送，即使文件扩展名为 .csv 也不会拆分为多列。

表头声明列名后，该列才按参数处理；未声明的列按备注原样保留。列名不区分大小写，并忽略空格与 `(ms)` 等括注：

- 名称：名称、名字、标签、指令名、name、label、title
- 指令：指令、命令、内容、指令内容、发送内容、cmd、command、value、data
- 顺序号：顺序号、顺序、序号、次序、序、order、seq、sequence
- 超时：超时、超时时间、超时毫秒、等待、等待时间、timeout、wait
- 期望：期望、期望值、响应词、成功词、expect
- 重试：重试、重试次数、retry、retries
- 成功跳转：成功跳转、成功后、成功、ok跳转、okgoto、success、onsuccess
- 失败跳转：失败跳转、失败后、失败、err跳转、errgoto、fail、onfail、ongoto
- HEX：hex、hex开关、十六进制、格式、format、mode

`编号`、`no`、`num`、`index` 等列名不识别，以避免将 ID 列读取为顺序号并改写为 `0`。旧列名「延时」按「超时」解析：数值不变，含义改变，导入时提示一次；两列同时存在时以「超时」为准。

无表头的旧文件按以下规则读取：第 1 列为名称，第 2 列为指令，第 3 列及之后为备注；不会按列号映射参数。

文件开头为 `---`（YAML）或 `+++`（TOML）时，到配对收尾行为止整块原样保留，本版本不解释其内容（YAML 收尾行为 `---` 或 `...`，TOML 为 `+++`）。`baud`、`mode`、`lineEnding`、`delay`、`expect`、`timeout`、`hex` 等 key 会触发「暂不生效」提示：逐条参数需写入表头声明的列（超时 / 期望 / 重试 / HEX），波特率与行尾在面板中设置。收尾行缺失时会提示，并按「仅第一行为文件头」处理，正文继续解析。

### 导入提示

导入成功时默认不显示提示，列表和来源行已反映结果。以下情况各提示一次，以避免静默改变语义：

- 存在被跳过的行：超过 500 条、名称或指令超长；提示第一处行号与原因。
- 文件头包含上述不生效的 key，或文件头缺少配对收尾行。
- 使用了旧列名「延时」。
- 文件中包含「期望」或「重试」（面板不显示这两项，需直接编辑文件）。
- 文件中包含「成功跳转」或「失败跳转」，或跳转列存在无法识别的写法。
- 跳转指向不存在的顺序号：成功跳转按「下一条」、失败跳转按「终止」处理。
- 表头识别出列，但未写全顺序号、超时或 HEX：这几项仅保存在本机配置中。
- 文件包含多张表，被读取为多个循环组。

### 写回规则

- 注释、表头、分隔行和额外列按原位置保留，仅改写指令对应的单元格。
- 未修改的参数格按原文本写回：写入 `0`、`是` 或留空时，写回内容保持一致；仅修改过的值、面板新建的行和导出副本会规范化为 `0 / 3000 / true|false`。原本为空的单元格保持为空，不填充默认值。
- 不自动增加列：表头未写顺序号、超时或 HEX 时，写回不增加列，这三项仅保存在本机配置中（导入时提示一次）。需要自包含文件时使用「导出」。
- 仅一组时，写回不新增 `##` 抬头（文件中已有抬头则原样保留）；拖动组、改名或删除组会同步修改文件中对应的表格。
- 整行为空的条目不写回；表头声明顺序号、超时或 HEX 的文件中，未填写指令但参数格有值的行会保留，以保证面板与文件的条目数一致。
- 写回前比对内容哈希：文件被其他编辑器修改时报冲突，不覆盖。仅成功读取过一次且持有哈希的关联文件允许写回。
- 写入采用临时文件加 rename 的原子方式；编码沿用读取时的设置：优先 UTF-8（含 BOM），失败时回退 GBK；GBK 无法编码的字符回退为 UTF-8。

### 导出与写回

| | 写回关联文件 | 导出副本 |
|---|---|---|
| 列 | 按文件表头，不补列 | 补全 顺序号 / 指令 / 超时(ms) / HEX / 期望 / 重试 / 成功跳转 / 失败跳转 |
| 名称列 | 原样保留 | 不写入 |
| 组抬头 | 仅一组时不写 | Markdown / TSV 副本一定写入；纯指令行且仅一组时无抬头 |
| 载体 | 沿用原载体 | 默认 Markdown / TSV；纯指令行且仅一组时保持一行一条，多组时升级为 Markdown 表格并提示 |
| 说明 | 不修改关联文件 | Markdown / TSV 副本开头包含 `#` 注释形式的用法说明和示例；纯指令行副本不包含 |

Markdown / TSV 副本开头的注释块包含表格示例、仅含「指令」列的 DSL 示例、HEX 示例和各列取值说明，可作为语法参考。该注释块仅出现在导出副本中，写回关联文件时不会添加任何内容。

导出直接写入文件，不执行写回的哈希冲突检测。若目标文件正被其他监视器关联，其内容会被替换；面板会立即提示，可在对应分栏执行「重载」或改用其他文件名。

默认文件名按监视器区分，避免连续两次导出互相覆盖：主分栏为 `quick-cmds.md`（TSV 为 `quick-cmds.tsv`），WSL、额外分栏和蓝牙页内嵌监视器各带标识（如 `quick-cmds-wsl.md`、`quick-cmds-extra-1.md`）。

## 上限

| 项 | 上限 | 超限行为 |
|---|---|---|
| 文件大小 | 256 KB | 读取和写入均被后端拒绝并提示 |
| 条目数 | 500 条 | 导入时超出的行跳过并提示；面板中无法继续添加，并提示先删除条目 |
| 名称 | 64 字符 | 导入时截断并提示 |
| 组名 | 64 字符 | 直接截断 |
| 单条指令 | 4096 字符 | 面板输入框限制为该长度；导入时超出会截断并提示；通过 MCP 修改时超出会被拒绝并提示 |

## 常见问题

指令只发送一次后停止：该条目设置了「期望」，但设备回话与整行 `OK` 或所写成功词不一致。等待超时后按失败处理，而失败跳转默认终止整条链。处理方式为：将设备实际返回的整行写入「期望」（多个词用 `|` 分隔），或将「期望」留空，使条目按超时间隔发送且不校验回话。

循环发送需要停止：点击标题行左侧的「循环发送」开关。连接断开、监视器关闭、发送失败或没有可发送条目时，循环也会自动停止；开关状态不保存，重启程序不会自动开始。

面板修改未写入文件：写回需要成功的读取基线。文件未成功读取（被删除、路径变化、超过 256 KB）时，程序不会写入，也不会用内存中的列表重写文件。此时点击来源行的「重载」；若提示冲突，说明文件被其他编辑器修改，重载后再修改。

导入后条目减少：整行为空的条目会被跳过。未填写指令但参数格有值的行（例如顺序号 0、超时 3000）会保留。

导出副本增加列与 `##` 抬头：Markdown / TSV 导出为自包含副本，会补全列并写入抬头；写回关联文件时不执行这两项操作。纯指令行且仅一组时，导出保持一行一条，仅包含指令内容；需要携带顺序号、超时等参数时，应使用 Markdown 或 TSV 载体导出。

文件头中的 `baud: 115200` 未生效：文件头整块保留但不解释。`baud`、`mode`、`lineEnding`、`delay`、`expect`、`timeout`、`hex` 会触发「暂不生效」提示；波特率等设置在面板中修改，逐条参数写入表头声明的列。

旧文件「延时」列：该列按「超时」读取，设置「期望」时为等待回话上限，未设置「期望」时为下一条发送间隔。数值不变，导入时提示一次；建议将列名改为「超时(ms)」。

期望与设备回话不匹配：期望采用整行相等判定，不支持包含匹配。需要包含或正则匹配时，使用工作流规则；或将设备实际返回的整行原样写入「期望」。

列名、文件头、写回规则和上限的完整说明见
[QUICK_CMDS.md](https://github.com/SeaHi-Mo/Seahi-Serial/blob/main/doc/QUICK_CMDS.md)。
