# 快速指令

快速指令面板在输出区右侧，默认折叠。点一下展开，向左拖动折叠条可以调宽：最窄 300px，最宽不超过窗格的 60%，并始终给输出区留 160px。它用来执行一组需要来回交互的指令，例如配网、校准或批量写入参数。

标题行左侧是「循环发送」开关，右侧是「＋ 新建循环组」「导入」「导出」。导入文件后，标题下方多出来源行：文件名、「重载」、「断开」。没挂文件时列表随本机配置保存；挂上文件后文件才是存储，配置里留一份缓存，读不到文件时保留它。

## 分组

指令按循环组管理。每组是一张自己的表：组抬头 → 列标题 → 数据行，和文件里「一组一张表」的形状一致。

- 组名直接在抬头里改。挂了文件时这行会同步改写文件里的 `## 组名`；老文件没有抬头时只改面板，不会凭空给文件加抬头。
- 按住抬头左侧的点阵握把上下拖动调顺序。最上面那组是循环起点，文件里几张表的顺序也会跟着换。
- 折叠箭头只收起显示，不影响循环。
- 抬头上的滑动开关控制这一组参不参与循环：关掉整组跳过、顺序号不变，重新打开恢复。开关和折叠状态存在本机配置里，外部文件没有组级开关这一列。
- 抬头显示这一组的条数，最右侧的 × 删除整组和组内指令。只剩一组时删不掉，可以删掉组里的指令。
- 列标题最右侧是「＋ 添加」，往这一组末尾加一条空指令。新建组追加在最下面，名字默认「循环 N」，自带一条空指令；挂了文件时会在文件末尾补出这一组的抬头、表头和这一行。

## 一条指令的字段

| 字段 | 说明 |
|---|---|
| 顺序号 | 最多 4 位数字。`0` = 不参与循环；大于 `0` 的在组内按数字升序发送，同号按行序 |
| 指令 | 原样发送；`\r\n`、`\t` 这类转义会生效；在输入框里按回车等于点这一条的发送按钮 |
| 超时(ms) | 这一条占用的时间，默认 3000，上限 600000（10 分钟）；含义见下节 |
| HEX | 本条按十六进制解析后发送，和主发送栏当前的文本/HEX 模式无关 |
| 发送 / 删除 | 单独发这一条（未连接时不可用），或删除 |

名称没有面板入口：文件里的名称列会原样保留，导出副本不带这一列。期望、重试、成功跳转、失败跳转也只有文件里有：写了它们，超时那一格会描一道淡边，悬停能看到具体内容，导入时也会提示一次。

## 超时与「期望」

「超时」的两种用法由「期望」有没有内容决定：

- 期望非空且超时大于 0：超时是发出去之后等回话的上限。等到成功词就提前走，等满走失败出口。
- 期望留空：这条不校验回话，超时就是发下一条之前的间隔。填 3000 就每 3 秒发一条。
- 超时填 0：不等（有期望也不等回话），按 20ms 的最小间隔连发。
- 把超时输入框清空会回到默认 3000，不是 0。

只有文件表头声明了「期望」列并写了内容，条目才会等回话。没有成功词就没有“什么算成功”，内置的 OK 也不会被拿来兜底——想等内置 OK 就把 `OK` 写进期望列。

## 等回话怎么判定

回话按行判定，判定在后端做一份，前端只负责发、等、按结论走下一步：

- 回话要带换行（`\r` 或 `\n`）才会被切成行；被拆成两块的半行会拼起来，一直没行尾的数据会等到超时。
- 行里含 `busy`：继续等，不算结论、不重发，也不延长超时。
- 行里含 `error`：失败，重发本条。同时含 `busy` 的行按 busy 处理，继续等。
- 整行是 `OK`，或以 ` OK` 结尾（如 `SEND OK`）：成功。
- 整行等于「期望」里的某个词：成功。多个词用 `|` 分隔，例如 `WIFI GOT IP|OK`。比较时去掉首尾空白、忽略大小写，但是整行完全相等，不是包含。
- 认不出来的行不产生结论，继续等。

在会等回话的条目上，内置的 `OK` / `error` / `busy` 始终在，期望是在它们之上追加，不能关掉它们。所以“只认 WIFI GOT IP、不认 OK”做不到。需要“包含某个词”或正则判成功时，用工作流规则（更多设置 → 工作流，条件类型有字符串包含、正则表达式、精确字节）。

重试：收到 ERROR 后隔 300ms 重发，默认 3 次（总共最多尝试 4 次），上限 10，`0` 表示不重发。等满超时也算失败。失败后走失败跳转；没配失败跳转就终止整条链。终止时弹窗会写明是哪一组哪一条、等了多久；ERROR 用尽时写的是“连续 N 次收到 ERROR”。

前端每 60ms 问一次后端有没有结论，后端在查询时结算超时，前端另加 400ms 宽限，避免抢答。

## 循环发送

开启前检查两件事：监视器已连接；参与循环的组里至少有一条顺序号大于 0 的指令。不满足就当场拒绝并说明原因，不会出现“开关亮着但什么都不发”。

- 顺序是组从上到下、组内顺序号从小到大，走完最后一组回到最上面那组。顺序号 `0` 跳过，不占位置。
- 每一步都重新取一遍计划：循环中改顺序号、拖组、加减条目、改超时/期望/跳转，下一步就生效，不用重开。
- 成功跳转在收到成功词后走；失败跳转在超时或 ERROR 用尽后走。留空或 `下一条` = 顺序走，数字 = 跳到那个顺序号（可跨组），`结束` = 停下。失败跳转留空默认终止整条链。
- 没有“下一组”这种跳转，跨组只能靠顺序号。跳转按顺序号找；不同组用了同一个顺序号时，落到计划里先遇到的那条。
- 目标顺序号不存在：导入时提示一次；真跑到那一步，成功跳转按“下一条”、失败跳转按“终止”处理，原因写在控制台。
- 跳转列里认不出来的写法按“下一条”，导入时提示。
- 连续跳转超过 200 次自动停止（中间顺序走一步就清零），用来兜“只在几条之间打转”。

### 单条发送与发不出去

点某一条的发送按钮、或在指令输入框里按回车，只发这一条，不开循环、也不等回话。它和循环发送共用同一条发送路径：按这一条的 HEX 开关决定文本还是十六进制，文本按面板的行尾设置追加行尾，HEX 不追加；内容为空时不发送。手动发送失败会在输出区写一行错误。

循环里这几种情况分开处理：

- 条目内容为空：跳过这一条，继续走。连续跳过一整轮的条数说明整条链都没有内容可发，循环停止并提示。
- 连接已断开、写设备失败、HEX 内容格式非法：发送失败，整条链立刻停止，不会跳转到别的条目继续发。
- 正常收尾（成功跳转填「结束」）：静默停止，不弹窗。

循环运行时输出区一个字都不写：已发出、收到 OK、busy、重发、跳转、正常收尾、跳过全都不写。可见性只有面板——亮着的「循环发送」开关和折叠条上一闪一闪的小点。想知道某条等不等回话，看超时那一格的悬停说明。

自愈停止的触发：掉线（含 WSL 读轮询连续 3 次失败）、发送失败（连接断开、写设备报错、HEX 格式非法）、整轮都没有内容可发、没有顺序号大于 0 的条目、跳转死循环、ERROR 用尽、超时终止。这些停止只弹一次窗，原因是弹窗说的，异常详情在控制台。主动关开关不提示；关闭监视器会直接收掉定时器。

「循环发送」开关状态不保存，程序启动后不会自动开始发送；快速指令分栏每次打开也都从折叠开始。

## 挂到外部文件

「导入」弹原生文件框选一个文件，之后这一栏的增删改都会写回它（去抖 600ms），文件就是存储。可选的扩展名有 md、markdown、txt、tsv、csv，但格式只看内容，不看后缀。

- 路径只认你在原生文件框里选过的：后端有自己的白名单（最近 50 个），前端传任意路径会被拒。
- 同一个文件不能被两个监视器同时挂载：第二次「导入」会被拒绝，并提示先去哪边「断开」。
- 来源行的「重载」从文件重新读取。重载失败会保留当前列表并提示，不会清空；下次启动会自动重读，读不到则保留配置里的缓存。
- 关闭窗口前，还在 600ms 去抖里的写回会立刻刷掉。

### 文件怎么写

`## 组名` 抬头分隔循环组（两个及以上 `#`）；单个 `#` 和 `//` 开头仍是注释；注释、空行、表头按原位置保留。没有抬头的老文件读成一组：读取时不补抬头，写回也不改你的表结构。载体看内容自动识别（出现 `##` 抬头时按 Markdown 处理），写回沿用识别出的那一种：

| 载体 | 长相 |
|---|---|
| Markdown 表格 | 含 `\|`，推荐；列和分组都用表头与 `##` 抬头表达 |
| TSV | 用制表符分隔，例如从 Excel 直接粘贴 |
| 纯指令行 | 一行一条指令 |

换行统一写成 CRLF。解析绝不按逗号切分：`AT+CWJAP="ssid","pwd"` 是一次完整发送，就算文件叫 .csv 也不会被拆成多列。

表头声明了列名，那一列才会被当成参数；没声明的列一律当备注原样保留。列名不区分大小写，会抹平空格和 `(ms)` 这类括注：

- 名称：名称、名字、标签、指令名、name、label、title
- 指令：指令、命令、内容、指令内容、发送内容、cmd、command、value、data
- 顺序号：顺序号、顺序、序号、次序、序、order、seq、sequence
- 超时：超时、超时时间、超时毫秒、等待、等待时间、timeout、wait
- 期望：期望、期望值、响应词、成功词、expect
- 重试：重试、重试次数、retry、retries
- 成功跳转：成功跳转、成功后、成功、ok跳转、okgoto、success、onsuccess
- 失败跳转：失败跳转、失败后、失败、err跳转、errgoto、fail、onfail、ongoto
- HEX：hex、hex开关、十六进制、格式、format、mode

`编号`、`no`、`num`、`index` 这类列名刻意不认，避免把你的 ID 列读成顺序号再改写成 `0`。旧列名「延时」按「超时」解读：数值不变、含义变了，导入时提示一次；两列同时存在时以「超时」为准。

没有表头的老文件：第 1 列名称、第 2 列指令、第 3 列起是备注，绝不按列号硬塞参数。

文件开头是 `---`（YAML）或 `+++`（TOML）时，到配对收尾行为止整块原样保留，但本版不解释（YAML 收尾行是 `---` 或 `...`，TOML 是 `+++`）。其中的 `baud`、`mode`、`lineEnding`、`delay`、`expect`、`timeout`、`hex` 会提示“暂不生效”：逐条参数要写在表头声明的列里（超时 / 期望 / 重试 / HEX），波特率与行尾在面板上设。收尾行缺失时会提示，并按“只有第一行是文件头”处理，正文照常解析。

### 导入时会提示什么

导入成功本身不弹提示（列表已经显示出来、来源行有文件名）。下面这些情况会各提示一次，避免静默改语义：

- 有行被跳过：超出 500 条、名称或指令超长，提示第一处的行号与原因。
- 文件头里有上面那些不生效的 key，或文件头没有配对收尾行。
- 用了旧列名「延时」。
- 文件里有 `期望` / `重试`（面板不显示这两项，要改得直接编辑文件）。
- 文件里有 `成功跳转` / `失败跳转`，或跳转列里有认不出的写法。
- 跳转指向不存在的顺序号：成功跳转按“下一条”、失败跳转按“终止”处理。
- 表头认出了列、但没写全 顺序号 / 超时 / HEX：这几项只保存在本机配置里。
- 文件里有几张表，被读成几个循环组。

### 写回规则

- 注释、表头、分隔行、额外列按原位置保留，只改属于指令的那些格子。
- 没动过的参数格原样回吐：你写 `0`、`是`、留空，写回还是那些字；只有改过值、面板新建的行和导出副本才规范化成 `0 / 3000 / true|false`。原本空着的格保持空，不硬填缺省值。
- 不擅自补列：表头没写顺序号 / 超时 / HEX，写回一个字都不加，这三项只存在本机配置里（导入时提示一次）。想要自包含文件用「导出」。
- 只有一组时写回不新增 `## 抬头`（文件里原本就有的话原样保留）；拖组、改名、删组会跟着改文件里对应的那段表。
- 整行都空的条目不写回；但表头声明了顺序号/超时/HEX 的文件里，“还没填指令、参数格有值”的行会保留，否则面板与文件的条数对不上。
- 写回前比对内容哈希：文件被别的编辑器改过就报冲突、不覆盖。只有成功读过一次、手里有哈希的挂载才允许写回。
- 写入是临时文件加 rename 的原子写；编码沿用读入时那套：UTF-8（含 BOM）优先，失败回退 GBK，GBK 编不出来的字符退回 UTF-8。

### 导出和写回的区别

| | 写回挂载文件 | 导出副本 |
|---|---|---|
| 列 | 按你的表头，不补列 | 补全 顺序号 / 指令 / 超时(ms) / HEX / 期望 / 重试 / 成功跳转 / 失败跳转 |
| 名称列 | 原样保留 | 不写 |
| 组抬头 | 只有一组时不写 | Markdown / TSV 副本一定写；纯指令行且只有一组时没有抬头 |
| 载体 | 沿用原载体 | 默认 Markdown / TSV；纯指令行且只有一组时保持一行一条，多组时升级成 Markdown 表格并提示 |
| 说明 | 不动你的文件 | Markdown / TSV 副本开头带一段 `#` 注释的用法说明和案例；纯指令行副本不带 |

Markdown / TSV 副本开头那段说明里给了表格案例、只写「指令」一列的 DSL 案例、HEX 案例和各列取值，等于一份自带语法的模板，不想翻文档时导出一份看就行。这些说明只在导出物里出现，写回你的挂载文件时一个字都不会加。

导出是直接写文件，不走写回的哈希冲突检测。目标如果正好是另一个监视器挂载的文件，那边内容会被换掉，面板会当场提示：去那边点「重载」，或换个文件名重导。

默认文件名按监视器区分，避免连点两次导出互相覆盖：主分栏是 `quick-cmds.md`（TSV 时 `quick-cmds.tsv`），WSL、额外分栏、蓝牙页内嵌监视器各带自己的标识（如 `quick-cmds-wsl.md`、`quick-cmds-extra-1.md`）。

## 上限

| 项 | 上限 | 超了会怎样 |
|---|---|---|
| 文件大小 | 256 KB | 读写都被后端拒绝并提示 |
| 条目数 | 500 条 | 导入时多出的行跳过并提示；面板里加不进去，提示先删几条 |
| 名称 | 64 字符 | 导入时截断并提示 |
| 组名 | 64 字符 | 直接截断 |
| 单条指令 | 4096 字符 | 导入时截断并提示；通过 MCP 修改时会被拒绝并提示 |

## 常见问题

**一条指令只发了一次就停了？**
它多半写了「期望」，但设备回的不是整行 `OK` 或你写的成功词，等满超时按失败处理，而失败跳转默认就是终止整条链。两种改法：把设备实际回的那一整行写进「期望」（多个词用 `|`），或者把「期望」留空，让它变成不校验回话的间隔发送。

**循环一直在发，怎么停？**
点标题行左侧的「循环发送」开关。掉线、关监视器、发送失败、没有可发条目时它会自愈停止；开关状态不保存，重启程序不会自动开始。

**面板改了，文件没变？**
写回需要一份成功的读取基线。文件没成功读过（被删、路径变了、超过 256 KB）时程序宁可不写，也不会用内存里的列表重写你的文件。先点来源行的「重载」；重载提示冲突则说明文件被别的编辑器改过，重载后再改。

**导入后少了一条？**
整行都空的条目会被跳过。只是没填指令、参数格有值的行（例如顺序号 0、超时 3000）会保留。

**导出后多了列和 `##` 抬头？**
Markdown / TSV 导出的是自包含副本：补列、写抬头。写回挂载文件时不会做这两件事。纯指令行且只有一组时，导出仍是一行一条，只保留指令内容；要带上顺序号、超时这些参数，用 Markdown 或 TSV 载体导出。

**文件头里写了 `baud: 115200`，没生效？**
文件头整块保留但不解释。`baud` / `mode` / `lineEnding` / `delay` / `expect` / `timeout` / `hex` 会提示“暂不生效”，波特率这类设置在面板上改，逐条参数写进表头声明的列。

**老文件的「延时」列怎么算？**
现在按「超时」读：写了期望时是等回话上限，没写期望时是发下一条的间隔。数值不变，导入时提示一次；想自己掌控就改名成「超时(ms)」。

**设备回的是 `+CWJAP:WIFI GOT IP`，期望写 `WIFI GOT IP` 不认？**
期望是整行完全相等，不是包含。要按包含或正则判成功，用工作流规则；或者把设备实际回的那一整行原样写进期望。

列名、文件头、写回规则和上限等完整说明见
[QUICK_CMDS.md](https://github.com/SeaHi-Mo/Seahi-Serial/blob/main/doc/QUICK_CMDS.md)。
