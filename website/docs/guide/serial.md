# 串口调试

## 分栏

工具栏的「＋」可以新增一个监视器分栏。每个分栏有自己的端口、波特率、行尾和发送历史，互不影响。

- 可以同时看两块板子的输出，分别发送指令。
- 分栏可以关闭，关掉时对应的串口连接也会释放。

## 工具栏

| 控件 | 作用 |
|---|---|
| 查看模式 | 输出按文本或 HEX 显示 |
| 端口 | 选择 COM 口，插拔设备时自动刷新 |
| 波特率 | 常用档位加自定义输入 |
| 行尾 | 发送时追加 `\r`、`\n` 或 `\r\n` |
| 开始 / 停止监控 | 连接与断开 |
| 齿轮 | 展开数据位、停止位、校验位、DTR/RTS 等高级设置 |
| 清屏 / 保存日志 | 清空输出区，或选择路径导出日志 |

图标按钮包括显示行号、时间戳、消息回显、终端模式和命令行缓冲。

## 发送

文本模式按 UTF-8 发送。HEX 模式按字节发送，例如 `AA 55 01`。

行尾按工具栏的选择追加。发送 AT 指令时建议打开命令行缓冲，并把行尾设为 `\r\n`，详见[终端模式](/guide/terminal)。

每个分栏独立保存最近 50 条发送记录，按 `↑`、`↓` 翻看，按 `Esc` 关闭历史下拉。

## 日志与缓存

清屏只影响当前显示，不会删除已经写入磁盘的会话缓存。

串口打开期间有收发时，程序会自动缓存这次会话：

```
%APPDATA%\seahi-serial\log-cache\session-<时间戳>-<端口>.log
```

最多保留 10 个，新建时淘汰最旧的。需要长期保留时用「保存日志」另存，程序不会自动删除手动保存的文件。

## 断线重连

串口断开后程序会自动尝试重连，按钮显示「等待接入」，端口状态点也会变色。重连过程和结果不会写进日志窗口，输出区里始终只有设备数据。

## 工作流

在「更多设置 → 工作流」里可以配置规则：收到匹配的数据后自动执行动作，例如发送数据、切换 DTR/RTS 或保存日志。

规则可以单独启停。命中后会写入独立的 `workflow` 日志通道，方便事后查看自动发送的内容和时间。

启动规则相当于允许程序自动向设备写数据，界面上需要二次确认；通过 MCP 调用时必须带 `confirm:true`。

## 主题

顶栏提供 6 种风格，每种风格各有深浅两套，共 12 套主题。切换主题时，普通输出区和终端模式会一起更新。

## WSL 端口映射

顶栏的「WSL 端口映射」把 USB 串口映射进 WSL。

- 依赖 [usbipd-win](https://github.com/dorssel/usbipd-win)，安装包里已经包含。绑定和映射需要管理员权限。
- 支持自动映射和手动绑定。绑定过程中 Windows 会弹出授权窗口，需要在系统弹框上确认。
- 映射完成后，WSL 里会出现新的 `/dev/ttyUSB*` 或 `/dev/ttyACM*`。

## 在 WSL 分栏里调试

WSL 分栏可以直接在 WSL 内部打开串口并收发数据。背后使用一个 Python bridge，通过持久化 shell 减少每次启动的开销。

分栏里的「启动」用 Windows Terminal 打开对应的发行版。发行版名称来自 `wsl --list --verbose` 的真实结果；解析失败时界面会显示 WSL 的报错原文，不会拿错误的名称去启动。

读取轮询连续失败时，程序会把该分栏判定为掉线，界面显示「等待接入」。如果此时循环发送正在运行，也会随之停止。

系统没有 `sg` 或当前用户不在 `dialout` 组时，bridge 只在能非交互切换用户组的情况下使用 `sg`，否则直接运行 `python3`。缺少 `sg` 不影响启动；不在 `dialout` 组时，需要把用户加入该组，或通过 usbipd 指定设备。
