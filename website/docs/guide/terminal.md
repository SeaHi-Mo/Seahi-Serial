# 终端模式

工具栏的终端图标把输出区切成一块 **xterm.js 终端画布**。它不是给日志换个字体——是真正的终端语义：光标移动、清屏、颜色、alt-screen 都由 xterm 处理，串口那头跑 `vim`、`top` 这类全屏程序能正常显示和操作。

## 两种输入口径，各有各的场景

工具栏的「命令行缓冲」决定按键怎么发。**默认：串口分栏开、WSL 分栏关。**

| | 直发（缓冲关，WSL 默认） | 行缓冲（缓冲开，串口默认） |
|---|---|---|
| 敲字 | 每个按键立刻发 | 先在本地攒成一行 |
| 回车 | 只发 `CR (0x0D)` | 整行 + 工具栏「行尾」一次发出 |
| 退格 | 发 `0x7F` 给设备 | **本地擦除**，不回传设备 |
| 方向键 | `ESC[A/B/C/D` 原样发 | **本地编辑这一行**（↑↓ 翻命令历史，←→ 移动光标） |
| 回显 | 完全由设备 tty 负责 | 本地回显一份（设备若也回显会看到两份） |
| Tab | `HT (0x09)` 给设备 | `HT (0x09)` 给设备 |
| 适合 | Linux 控制台 / shell | **AT 指令、串口协议** |

::: warning AT 指令请用行缓冲
逐键发送 + 回车只给 `\r` + 退格 `0x7F` 被模组当垃圾丢掉，三条凑一起就是「AT 命令必错」。
行缓冲会攒整行、补行尾（通常选 `\r\n`），这才是模组期望的输入方式。
:::

设备如果开着回显（`ATE1`），你会看到两份字——属预期，`ATE0` 关掉设备侧回显即可。

## 这些是刻意的

- **不做本地 Tab 补全**：补全和历史交给设备上的 shell，本地猜只会猜错。
- **进入终端模式会自动发一个回车**：设备重新打印提示符，画布立刻有内容可看。未连接时不发。
- **不回放旧日志**：终端是会话态，退出终端模式回到普通输出区，切走期间的完整日志还在。
- **终端模式下「显示行号 / 时间戳 / 消息回显」会置灰**：这三项只作用于普通输出视图（终端由 xterm 自己排版、回显由设备负责）。只是外观变灰，**不会改掉你原来的开关**，退出后照旧生效。
- **配色跟主题走**：16 色 ANSI 调色板取自当前主题，和普通输出区**同一份 CSS 定义**。同一段彩色日志，在两种视图里颜色一致；切深浅色也跟着变。

## 普通输出区不主动上色

只有日志自带 **16 色 ANSI 转义**（30–37 / 90–97、粗体）才会按主题着色。**256 色与真彩色在普通模式不解析**，按纯文本显示——颜色能力只属于终端模式。日志视图保持干净，是刻意的取舍。

## 终端里敲的东西怎么进日志

逐字符记录会把日志刷满，所以只记**命令级**：

- 按回车提交时记一条，粘贴时记一条，都进 `serial:<分栏>:tx` 通道（来源标为 `ui`）。
- 按 ↑ 从设备侧 readline 历史里回填出来的命令，本机看不到原文，**宁可漏记也不编造**。

## 会话态

终端内容不持久化：关分栏、重开应用都从空白开始。要让某段输出留下来，用「保存日志」另存。
