# 终端模式

工具栏的终端按钮会把输出区切换成 xterm.js 画布。光标移动、清屏、颜色和全屏程序都由 xterm 处理，串口另一端的 `vim`、`top` 可以正常显示和操作。

## 什么时候用终端模式

- 串口另一端是 Linux 控制台或 shell，需要 readline 的行编辑、补全，以及全屏程序。
- 需要程序自己控制光标位置、清屏或切换备用屏幕，例如 `vim`、`top`、`less`。
- 普通输出区会把光标移动、擦除这类控制序列剥掉，只按行显示文本，这些画面只能在终端模式里还原。

只是看日志、保存日志、加行号和时间戳时，普通输出视图更合适。

## 打开与退出

- 点工具栏的终端图标进入终端模式。普通输出区和底部发送栏会隐藏，按键直接在画布上敲；要再用发送输入框，先退出终端模式。
- 每个分栏有自己的 xterm 实例，切走切回不会重建；关闭分栏时才销毁。程序重启后不会自动进入终端模式，画布从空白开始，终端历史不保存。
- 「清除内容」同时清空画布、普通输出缓冲和磁盘会话缓存。
- `Ctrl+Shift+C` 复制选中的文字。`Ctrl+C` 不复制，它作为 `0x03` 中断发给设备。
- 画布可以向上滚，xterm 保留最近 5000 行；收到新数据自动滚到底。
- 进入终端模式时会向设备发一个回车（`CR`），设备重新打印提示符，画布立刻有内容。未连接时不发，也不回放普通输出区的旧日志、不弹本地提示。

## 键盘与画布

- 进入终端模式后画布自动获得焦点，可以直接敲键；点到别处后再点一下画布即可继续。
- 鼠标滚轮和滚动条都作用于 xterm 自己的回滚缓冲，不影响普通输出区的滚动位置。
- 选区用鼠标拖动产生，复制只走 `Ctrl+Shift+C`。
- 支持全屏程序：`vim` 打开和退出时，备用屏幕的进入与还原由 xterm 处理，退出后回到原来的画面。

## 尺寸与排版

- 画布尺寸随分栏宽度和窗口大小变化重新计算列数与行数，切换页面或拉宽分栏后会自动适应。
- 串口没有 PTY 行规，这个尺寸只决定画布怎么排版。设备收不到窗口大小变化，全屏程序只能按默认值或自己预设的尺寸绘制。

## 直发与行缓冲

工具栏的「命令行缓冲」决定按键如何发送。串口分栏默认开启行缓冲，WSL 分栏默认关闭。切换这个开关会清掉敲了一半的行。

| | 直发（缓冲关闭） | 行缓冲（缓冲开启） |
|---|---|---|
| 敲字 | 每个按键立即发送 | 先在本地累积成一行 |
| 回车 | 只发送 `CR (0x0D)` | 整行连同工具栏的行尾一起发送 |
| 退格 | 发送 `0x7F` | 只在本地擦除，不发给设备 |
| 方向键 | 原样发送 `ESC[A/B/C/D` | 在本地编辑当前行，上下键翻历史 |
| 回显 | 由设备 tty 负责 | 本地回显一份 |
| Tab | 发送 `HT (0x09)` | 发送 `HT (0x09)` |
| 适用场景 | Linux 控制台、shell、全屏 TUI | AT 指令、串口协议 |

## 直发

- 按键原样发给设备：回车 `0x0D`、Tab `0x09`、方向键 `ESC[A` 这类序列、Ctrl 组合键都照原样。
- 不追加行尾，也不拦截任何键。`vi`、`top` 这类全屏程序和 shell 的 readline 都靠它。
- 粘贴内容原样发送，包括其中的换行。

## 行缓冲

- 可打印字符先进本地缓冲并回显，按回车才把「整行 + 行尾」一次发出。空行按回车只发一个行尾。
- 退格（`0x7F` / `0x08`）只在本地删字符，不发给设备。
- 左右方向键移动光标，Home / End 跳到行首行尾，Delete 删光标处的字符，↑ / ↓ 翻本地命令历史。这些键都不发给设备。
- 历史最多 200 条，连续相同的不重复记。历史只存在这个分栏里，关分栏或退出程序后清空。
- `Ctrl+C` 先把敲了一半的行冲掉，再发 `0x03` 中断；`Ctrl+U` 擦掉当前行，不发给设备。
- Tab 和其余控制键照常直发；F1–F12、PgUp、PgDn 这类功能键也原样发给设备。
- 单行上限 8192 字符。到了上限会直接把缓冲发出去，这次不带行尾，也不进历史。长数据请分多条发。
- 本地回显按「一个字符一列」计算，中文或 emoji 这类宽字符会错位。行缓冲面向 AT 指令这类 ASCII 内容，需要正常显示宽字符时用直发模式。

行缓冲适合 AT 指令：逐键发送、回车只给 `\r`、退格 `0x7F` 被模组当作无效字节，这三点都会让 AT 命令出错。行缓冲把整行攒好再补上行尾，模组才能正确识别。

设备如果开了回显（`ATE1`），输入内容会显示两份，这是正常现象。关闭设备回显（`ATE0`）即可。

## 粘贴与命令记录

逐字符记日志会刷屏，所以终端模式只记命令级操作：

- 回车提交时记一条，粘贴时按行各记一条，写入 `serial:<分栏>:tx` 通道，来源标记为 `ui`。
- 一次给出多个可打印字符按粘贴处理；方向键这类纯转义序列不记，不会把 `[A` 当成用户敲的字符。
- 按 `↑` 从设备侧 readline 历史里回填的命令，本机没有收到那串字符，所以不记。宁可漏记也不编造。
- 发送失败时画布上打一行红色的 `[发送失败]`，详细原因在开发者控制台。
- 行缓冲里按回车提交的整行（含行尾）和直发模式下的按键流，都会走与普通发送相同的发送命令，超时 5 秒。

## WSL 分栏里的终端模式

WSL 分栏用同一套终端按钮和 xterm 画布，区别在默认值：

- 命令行缓冲默认关闭，逐键直发，保留 Linux shell 的 readline、补全和方向键。
- 要发 AT 类整行命令时再手动打开行缓冲。
- 普通输出区同样只是隐藏，WSL 分栏的日志与日志中心照旧工作。

## 终端模式与普通输出区的分工

- 普通输出区在终端模式下只是隐藏，日志行照常生成，行号和时间戳照常计算，只是看不到；退出终端模式就能看到完整历史。
- 会话缓存、日志中心和 MCP 的 `serial_get_output` 读的都是普通输出区那份文本，终端画布不额外落盘。
- 「清除内容」两处一起清：画布、输出区缓冲和磁盘缓存文件。
- 退出终端模式不会把画布内容回放到输出区，画布与输出区各自记录自己的显示内容。

## 终端模式下的控件

| 控件 | 终端模式下的行为 |
|---|---|
| 清除内容 | 清空画布、普通输出缓冲和当前会话缓存 |
| 显示行号 / 时间戳 / 消息回显 | 置灰，只作用于普通输出视图 |
| 命令行缓冲 | 可用，决定按键是直发还是整行发送 |
| 发送输入框 | 隐藏，按键直接在画布上敲 |
| 保存日志 / 复制全部 | 照旧，按普通输出区的完整文本操作 |
| 更多设置（日志目录、工作流） | 照旧可用 |

## 配色

- 16 色 ANSI 跟随当前主题，和普通输出区用同一份颜色定义，12 套主题各一份。
- 背景和前景取输出区实际配色，光标和选区取主题的强调色，选区半透明。
- 切换主题或深浅色后立刻重建配色，切回终端模式时颜色已经对了。

## 普通输出区不主动上色

普通输出区只解析日志自带的 16 色 ANSI 转义（30–37、90–97 和粗体）。256 色和真彩色按纯文本显示。颜色能力只存在于终端模式。

## 终端模式下置灰的项

「显示行号」「时间戳」「消息回显」只作用于普通输出视图，进入终端模式后置灰；鼠标停在上面会说明原因。

置灰只改外观，不动你原来的开关状态，退出终端模式后照旧生效。

反过来，「命令行缓冲」只对终端模式有效，终端模式关着时置灰。
