# 终端模式

工具栏中的终端按钮将输出区切换为 xterm.js 画布，光标移动、清屏、颜色与全屏程序均由 xterm 处理，串口另一端的 `vim`、`top` 等程序可正常显示与操作。

## 什么时候用终端模式

终端模式适用于以下场景：

- 串口另一端为 Linux 控制台或 shell，需要 readline 行编辑、补全与全屏程序。
- 程序需要控制光标位置、清屏或切换备用屏幕，例如 `vim`、`top`、`less`。

普通输出区会剥离光标移动与擦除等控制序列，仅按行显示文本，因此上述画面只能在终端模式下还原。仅需查看日志、保存日志或添加行号与时间戳时，使用普通输出视图即可。

## 打开与退出

点击工具栏中的终端图标进入终端模式，普通输出区与底部发送栏随即隐藏，按键直接发送至终端画布；如需使用发送输入框，应先退出终端模式。

每个分栏拥有独立的 xterm 实例，切换分栏或页面时复用实例，关闭分栏时销毁。程序重启后不恢复终端模式，画布从空白开始，终端历史不保存。

「清除内容」同时清空画布、普通输出缓冲与磁盘会话缓存。`Ctrl+Shift+C` 复制选中文本；`Ctrl+C` 不作为复制快捷键，而是以 `0x03` 发送给设备。

画布支持向上滚动，xterm 保留最近 5000 行，收到新数据时自动滚动至底部。进入终端模式时，若端口已连接，程序向设备发送一个回车（`CR`），设备随后重新打印提示符；程序不回放普通输出区的旧日志，也不显示本地提示。

## 键盘与画布

进入终端模式后画布自动获得焦点，可直接输入；焦点移至其它区域后，点击画布可重新获得焦点。

鼠标滚轮与滚动条作用于 xterm 自身的回滚缓冲，不影响普通输出区的滚动位置。选区通过鼠标拖动产生，复制操作使用 `Ctrl+Shift+C`。

全屏程序由 xterm 处理备用屏幕的进入与还原，程序退出后恢复原有画面。程序不在本地实现 Tab 补全，Tab 按键发送至设备，由设备侧 shell 处理补全。

## 尺寸与排版

画布尺寸随分栏宽度与窗口大小变化重新计算列数与行数，切换页面或调整分栏宽度后自动适应。

串口没有 PTY 行规，该尺寸仅决定画布的排版方式；设备收不到窗口大小变化，全屏程序按默认值或自身预设尺寸绘制。

## 直发与行缓冲

工具栏中的「命令行缓冲」决定按键的发送方式。串口分栏默认开启行缓冲，WSL 分栏默认关闭；切换该开关会清空已输入但未提交的内容。

| | 直发（缓冲关闭） | 行缓冲（缓冲开启） |
|---|---|---|
| 敲字 | 每个按键立即发送 | 先在本地累积成一行 |
| 回车 | 只发送 `CR (0x0D)` | 整行连同工具栏的行尾一起发送 |
| 退格 | 发送 `0x7F` | 只在本地擦除，不发给设备 |
| 方向键 | 原样发送 `ESC[A/B/C/D` | 在本地编辑当前行，上下键翻历史 |
| 回显 | 由设备 tty 负责 | 本地回显一份 |
| Tab | 发送 `HT (0x09)` | 发送 `HT (0x09)` |
| 适用场景 | Linux 控制台、shell、全屏 TUI | AT 指令、串口协议 |

## 直发

- 按键原样发送至设备：回车为 `0x0D`，Tab 为 `0x09`，方向键为 `ESC[A` 等序列，Ctrl 组合键同样原样发送。
- 不追加行尾，不拦截按键；全屏程序与 shell 的 readline 依赖该模式。
- 粘贴内容原样发送，包括其中的换行。

## 行缓冲

- 可打印字符先进入本地缓冲并回显，按回车时将「整行 + 行尾」一次发送；空行按回车仅发送行尾。
- 退格（`0x7F` / `0x08`）仅在本地删除字符，不发送至设备。
- 左右方向键移动光标，Home 与 End 移至行首或行尾，Delete 删除光标处字符，↑ 与 ↓ 翻阅本地命令历史；这些按键不发送至设备。
- 历史最多保留 200 条，连续相同的记录只保存一条；历史仅存在于当前分栏，关闭分栏或退出程序后清空。
- `Ctrl+C` 先清除已输入但未提交的内容，再发送 `0x03` 中断；`Ctrl+U` 清除当前行，不发送至设备。
- Tab 与其余控制键照常直发，F1 至 F12、PgUp、PgDn 等功能键原样发送至设备。
- 单行上限为 8192 字符；达到上限时程序直接发送缓冲内容，本次不带行尾，也不进入历史。长数据应分多条发送。
- 本地回显按一个字符一列计算，中文与 emoji 等宽字符会错位；行缓冲面向 AT 指令等 ASCII 内容，需要正常显示宽字符时应使用直发模式。

行缓冲适用于 AT 指令：逐键发送、回车仅发送 `\r`、退格 `0x7F` 被模组视为无效字节，这三种情况都会导致 AT 命令无法正确解析。行缓冲将整行缓存后补上行尾，模组可正确识别。

设备开启回显（`ATE1`）时，输入内容会显示两份，属于正常现象；关闭设备回显（`ATE0`）即可。

## 粘贴与命令记录

终端模式仅记录命令级操作，逐字符记录会使日志难以阅读：

- 回车提交时记录一条，粘贴时按行各记录一条，写入 `serial:<分栏>:tx` 通道，来源标记为 `ui`。
- 一次输入多个可打印字符按粘贴处理；方向键等纯转义序列不记录，不会将 `[A` 识别为用户输入。
- 通过 `↑` 从设备侧 readline 历史回填的命令，本机未接收到对应字符，因此不记录。
- 发送失败时，画布显示一行红色 `[发送失败]` 文本，详细原因写入开发者控制台。
- 行缓冲按回车提交的整行（含行尾）与直发模式的按键流使用相同的发送命令，超时时间为 5 秒。

## WSL 分栏里的终端模式

WSL 分栏使用同一套终端按钮与 xterm 画布，默认值不同：

- 命令行缓冲默认关闭，按键逐键直发，保留 Linux shell 的 readline、补全与方向键。
- 需要发送 AT 类整行命令时，手动开启行缓冲。
- 普通输出区同样保持隐藏，WSL 分栏的日志与日志中心继续工作。

## 终端模式与普通输出区的分工

普通输出区在终端模式下仅隐藏，日志行照常生成，行号与时间戳照常计算，退出终端模式后可查看完整历史。

会话缓存、日志中心与 MCP 的 `serial_get_output` 均读取普通输出区的文本，终端画布不额外写入磁盘。

「清除内容」同时清理画布、输出区缓冲与磁盘缓存文件。退出终端模式不会将画布内容回放至输出区，画布与输出区分别维护各自的显示内容。

## 终端模式下的控件

| 控件 | 终端模式下的行为 |
|---|---|
| 清除内容 | 清空画布、普通输出缓冲和当前会话缓存 |
| 显示行号 / 时间戳 / 消息回显 | 置灰，只作用于普通输出视图 |
| 命令行缓冲 | 可用，决定按键是直发还是整行发送 |
| 发送输入框 | 隐藏，按键直接在画布上输入 |
| 保存日志 / 复制全部 | 照旧，按普通输出区的完整文本操作 |
| 更多设置（日志目录、工作流） | 照旧可用 |

## 配色

- 16 色 ANSI 跟随当前主题，与普通输出区使用同一份颜色定义，12 套主题各一份。
- 背景与前景取自输出区实际配色，光标与选区使用主题强调色，选区为半透明。
- 切换主题或深浅色后立即重建配色，切回终端模式时颜色已更新。

## 普通输出区不主动上色

普通输出区仅解析日志自带的 16 色 ANSI 转义（30–37、90–97 与粗体）；256 色与真彩色按纯文本显示，颜色能力仅在终端模式中提供。

## 终端模式下置灰的项

「显示行号」「时间戳」「消息回显」仅作用于普通输出视图，进入终端模式后置灰，悬停提示说明原因。

置灰仅改变外观，不修改原有开关状态，退出终端模式后开关继续生效。相反，「命令行缓冲」仅对终端模式有效，终端模式关闭时置灰。
