# WSL 端口映射

顶栏的「WSL 端口映射」用于将 USB 设备映射进 WSL，使设备在 WSL 内以 `/dev/tty*` 串口形式访问。映射依赖 [usbipd-win](https://github.com/dorssel/usbipd-win)，安装包已包含该工具。

## 打开面板

点击标题栏的 WSL 图标进入面板，图标变为「返回到串口调试器」；再次点击或点击应用图标可返回串口页。主串口分栏保持连接但隐藏，接收轮询间隔由 25ms 调整为 500ms，返回后恢复。

WSL 页面中的「打开额外监视器」按钮用于新增 WSL 分栏；WSL 未运行时该按钮置灰。

## 发行版

面板顶部依据 `wsl --list --verbose` 的真实输出列出本机所有发行版：

- 每张卡片带一个状态点：绿色表示运行中，灰色表示已停止；默认发行版在「映射到」下拉列表中标注为默认。
- 运行中的卡片显示 `UP` 与运行时长，每秒刷新，按钮为「关闭」。
- 已停止的卡片按钮为「启动」。
- 卡片右侧的终端图标通过 Windows Terminal 打开该发行版；发行版未运行时按钮不可用。

启动发行版时，程序先核对名称确实存在于 WSL 返回的发行版列表中，再执行启动。启动优先使用 Windows Terminal，命令为 `wt -p <发行版>` 并显式指定 `wsl.exe -d <发行版>`，即使 profile 名称不匹配也不会启动错误程序；系统没有 `wt.exe` 时退回 `conhost.exe`。启动失败时弹出提示，不启动窗口。

关闭发行版执行 `wsl --terminate <发行版>`。关闭后，已映射设备在列表中回退为未映射状态，WSL 分栏整体置灰并断开连接。

无法读取发行版列表时，面板显示 WSL 的原始报错文本，不生成发行版卡片。后台每 2 秒检查一次 WSL 状态，变化推送至界面。

「映射到」下拉列表用于指定目标发行版：留空表示默认发行版；存在多个发行版时，映射操作显式携带 `--distribution <名称>`。

## 设备列表

设备表来源于 `usbipd list`，每 5 秒刷新一次；插拔设备时也会立即触发一次刷新。

| 列 | 说明 |
|---|---|
| BUSID | usbipd 的设备编号，例如 `1-4` |
| 端口 | 已映射时显示 WSL 中的设备路径，例如 `/dev/ttyUSB0`；否则显示 `—` |
| 设备名称 | USB 设备名，下方显示 VID:PID 与序列号 |
| 状态 | 绿色表示空闲可用；黄色表示端口正被监视器占用；红色表示已映射但未解析到 WSL 路径 |
| 自动 | 按 VID:PID 记录「插入时自动映射」 |
| 映射 | 勾选后映射设备，取消勾选解除映射 |

串口、蓝牙、内置 HID、USB 网卡、指纹设备与摄像头不会出现在该表中。串口与蓝牙分别使用对应面板；网卡映射进 WSL 会覆盖 WSL 自身的网络配置；指纹设备映射后 Windows Hello 无法使用本机指纹。找不到设备时，可尝试以管理员身份运行程序。

映射前有两项检查：

- WSL 未运行时，「映射」复选框置灰，无法勾选。
- `usbipd` 未安装或不在 PATH 中时，映射操作直接返回错误，并提示先安装 usbipd-win。

## 映射与取消映射

勾选「映射」将设备 attach 到 WSL：

- 设备尚未通过 usbipd 共享时，先执行 `bind` 再执行 `attach`，该步骤需要管理员权限。
- 已共享的设备可直接 attach，不需要提权。
- 目标 COM 口仍在监控时，程序先停止该分栏的监控，再执行 attach，避免读线程连续报错。
- 需要提权时采用两阶段流程：程序先探测权限，需要提权时在应用内显示「授权确认」窗口；点击「授权并映射」后才触发系统 UAC。该窗口 60 秒内无操作按取消处理。
- 映射完成后，设备行显示 WSL 路径。路径解析存在延迟，程序自动重试，最多 4 次，每次间隔 1 秒。

取消勾选执行 detach：

- 若 WSL 分栏正在使用该路径，程序先断开该分栏，再执行 detach。
- detach 同样可能需要提权。

自动映射的规则如下：

- 打开某台设备的「自动」开关后，程序按 VID:PID 记录该规则；设备未处于已映射状态时，后台每 15 秒检查一次，插拔事件到达时也会立即检查。
- 自动映射需要提权时直接触发系统 UAC，不显示应用内确认窗口。
- 同一条规则连续失败 3 次后暂停并提示一次，避免反复触发 UAC；重新开关自动映射可重置计数。

## 在 WSL 分栏里调试

面板下半部分为 WSL 分栏，默认高度 300px，可通过拖动中间分隔条调整，最低 120px；高度随配置保存。

WSL 分栏工具栏与串口分栏一致，包含查看模式、端口、刷新、波特率、行尾、开始与停止监控、清除内容、自动滚动、自动重连、终端模式、命令行缓冲、行号、时间戳、消息回显与更多设置。命令行缓冲默认关闭，因为 Linux shell 依赖 readline 与方向键；需要发送 AT 类整行命令时可手动开启。

端口列表来自 WSL 内的 `/dev/ttyACM*`、`/dev/ttyUSB*` 与 `/dev/ttyS*`。下拉列表展开时显示「路径(设备名)」，选中后仅显示路径；被其它分栏占用的路径标记为「占用中」，不可选择；列表为空时显示「无可用端口」，需先确认发行版正在运行且设备已映射。

连接时后端执行以下操作：

- 查找运行中的发行版，若不存在则启动默认发行版，并将 bridge 脚本部署到 WSL 的 `/tmp`。
- 使用 `python3` 启动 bridge 进程。仅当能够非交互切换至 `dialout` 组时使用 `sg`，否则直接运行 `python3`，避免 `sg` 停留在密码提示。
- 等待 bridge 输出 `ready`，最长 5 秒；之后收发数据均通过该管道。

连接失败时，提示区分以下原因：

- 缺少 `python3`：在发行版中安装 `python3` 与 `python3-serial`。
- 缺少 `sg`：安装 `shadow` 包，安装后重新连接，程序会自动改用该路径。
- `dialout` 组不匹配：部分发行版的串口组名为 `uucp` 或 `tty`，也可能是当前用户不在组内。
- bridge 启动超时：脚本未写入 `/tmp`，或 `/tmp` 不可写或已满；重新连接会重新部署。

掉线判定规则如下：读轮询每次超时 3 秒，连续 3 次失败即判定设备断开。程序随即断开连接、结束会话缓存、将界面切回未连接，并弹出一次提示；该提示仅弹窗，不写入日志窗口，技术细节保留在控制台。

自动重连默认关闭。开启后最多重试 10 次，间隔为 3 秒乘以尝试次数，最长 30 秒；重连过程与结果同样不写入日志。

WSL 分栏的收发、发送历史、日志缓存、工作流与终端模式行为与串口分栏一致。映射设备被 detach 后，WSL 中的 `/dev/tty*` 节点消失，连续读失败会触发上述掉线判定。

## 常见问题

- 端口列表持续为空：确认发行版正在运行而非仅打开 Windows Terminal 窗口；返回面板确认映射状态与 WSL 路径是否已出现；点击刷新；必要时取消映射后重新映射；也可在 WSL 中执行 `ls /dev/ttyUSB* /dev/ttyACM*` 确认节点存在。
- 「映射」复选框置灰：WSL 未运行，需先启动一个发行版。
- 映射失败：检查授权窗口是否被取消、usbipd 是否已安装、设备是否仍处于连接状态；设备被其它程序占用时需先释放。
- 打开终端失败：卡片区域会弹出提示，按提示检查 `wt.exe` 与发行版状态。
- 无法读取发行版列表：面板显示 WSL 原始报错，常见原因为 WSL 未安装、没有发行版，或 `wsl --list --verbose` 被拒绝访问。
