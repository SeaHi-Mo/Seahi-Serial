# WSL 端口映射

顶栏的「WSL 端口映射」把 USB 设备映射进 WSL，之后可以在 WSL 里直接访问 `/dev/tty*` 串口设备。映射依赖 [usbipd-win](https://github.com/dorssel/usbipd-win)，安装包里已经包含。

## 打开面板

点标题栏的 WSL 图标进入。进入后这个图标变成「返回到串口调试器」，再点一次回串口页；点应用图标也能回去。主串口分栏被隐藏但不会断开，接收轮询从 25ms 降到 500ms，切回去恢复。

WSL 页里的「打开额外监视器」按钮用来新增 WSL 分栏；WSL 没有运行时这个按钮置灰。

## 发行版

面板顶部按 `wsl --list --verbose` 的真实结果列出本机所有发行版：

- 每张卡片一个状态点：绿色表示运行中，灰色表示已停止。默认发行版在「映射到」下拉里带「（默认）」后缀。
- 运行中的卡片显示 `UP` 和运行时长，每秒刷新一次；按钮是「关闭」。
- 停止的卡片按钮是「启动」。
- 卡片右侧的终端图标用 Windows Terminal 打开这个发行版；发行版没在运行时这个按钮不可用。

启动：

- 程序会先核对名字确实在 WSL 返回的发行版列表里，再启动它。
- 优先用 Windows Terminal（`wt -p <发行版>` 同时显式指定 `wsl.exe -d <发行版>`，profile 名对不上也不会开成 PowerShell）；没有 `wt.exe` 时退回 `conhost.exe`。
- 启动失败会弹提示，窗口不会开错。

关闭：执行 `wsl --terminate <发行版>`。关闭后，已映射的设备在列表里回退为未映射，WSL 分栏整体置灰并断开连接。

读不到发行版列表时，面板直接把 WSL 的原始报错显示出来，不会凭空造一张发行版卡片。后台每 2 秒检查一次 WSL 状态，变化会推给界面。

「映射到」下拉用来指定目标发行版：留空表示默认发行版；有多个发行版时，映射会显式带上 `--distribution <名字>`。

## 设备列表

设备表来自 `usbipd list`，每 5 秒刷新一次；插拔设备时也会立刻触发一次刷新。

| 列 | 说明 |
|---|---|
| BUSID | usbipd 的设备编号，例如 `1-4` |
| 端口 | 已映射时显示 WSL 里的设备路径，例如 `/dev/ttyUSB0`；否则显示 `—` |
| 设备名称 | USB 设备名，下面是 VID:PID 和序列号 |
| 状态 | 绿：空闲可用；黄：端口正被监视器占用；红：已映射但没解析到 WSL 路径 |
| 自动 | 按 VID:PID 记住「插入就自动映射」 |
| 映射 | 勾选映射 / 取消勾选解除映射 |

串口、蓝牙、内置 HID、USB 网卡、指纹和摄像头不会出现在这张表里：串口用串口面板、蓝牙用蓝牙面板，网卡映射进 WSL 会顶掉 WSL 自己的网络，指纹映射会抢走 Windows Hello。找不到设备时可尝试以管理员身份运行程序。

映射前有两道检查：

- WSL 没有运行：映射复选框是灰的，勾不动。
- `usbipd` 没有安装或不在 PATH：映射会直接报错并说明要先装 usbipd-win。

## 映射与取消映射

勾选「映射」等于把设备 attach 到 WSL：

- 如果设备还没被 usbipd 共享，先 `bind` 再 `attach`，这一步需要管理员权限。
- 已共享的设备可以直接 attach，不需要提权。
- 目标 COM 口还开着监控时，程序会先停掉那个分栏的监控，再执行 attach，避免读线程连续报错。
- 需要提权时是两阶段：先探测，需要权限就在应用内弹「授权确认」窗口，点「授权并映射」后才会走系统 UAC；这个窗口 60 秒不操作按取消处理。
- 映射完成后，设备行会显示 WSL 路径。路径解析有延迟，程序会自动重试最多 4 次、每次间隔 1 秒。

取消勾选等于 detach：

- 如果 WSL 分栏正在用这个路径，程序会先断开那个分栏，再执行 detach。
- detach 同样可能需要提权。

自动映射：

- 打开某台设备的「自动」开关后，程序按它的 VID:PID 记住这条规则；设备不在已映射状态时，后台每 15 秒检查一次，插拔事件到来时也会立刻检查。
- 自动映射需要提权时直接走系统授权框，不会先弹应用内的确认窗口；弹 UAC 属于预期。
- 同一条规则连续失败 3 次会暂停并提示一次，避免反复弹授权框；重新开关自动映射可重置计数。

## 在 WSL 分栏里调试

面板下半部分是 WSL 分栏，默认高度 300px，拖动中间的手柄可以调整，最低 120px，高度随配置保存。

WSL 分栏的工具栏和串口分栏一致：查看模式、端口、刷新、波特率、行尾、开始/停止监控、清除内容、自动滚动、自动重连、终端模式、命令行缓冲、行号、时间戳、消息回显和更多设置都能用。区别是命令行缓冲默认关闭（Linux shell 要 readline 和方向键），需要发 AT 这类整行命令时再打开。

端口列表来自 WSL 内的 `/dev/ttyACM*`、`/dev/ttyUSB*` 和 `/dev/ttyS*`：

- 下拉展开时显示「路径(设备名)」，选中后只显示路径。
- 被其它分栏占用的路径标为「占用中」，点不动。
- 列表为空时显示「无可用端口」，先确认发行版在运行、设备已映射。

连接时后端会做这几件事：

- 找运行中的发行版（没有就启动默认发行版），把 bridge 脚本部署到 WSL 的 `/tmp`。
- 用 `python3` 启动 bridge 进程。能非交互切换到 `dialout` 组时才用 `sg`，否则直接跑 `python3`，避免 `sg` 卡在密码提示上。
- 等 bridge 打出一行 `ready`，最多 5 秒；之后收发都通过这条管道。

连接失败时提示会区分原因：

- 没有 `python3`：发行版里先装 `python3` 和 `python3-serial`。
- 没有 `sg`：装 `shadow` 包；装好后重连一次，程序会自动改用它。
- `dialout` 组不对：有些发行版的串口组叫 `uucp` 或 `tty`，也可能当前用户不在组里。
- bridge 启动超时：脚本没落到 `/tmp`，或 `/tmp` 不可写/已满，重连会重新部署。

掉线判定：读轮询每次超时 3 秒，连续 3 次失败就判定设备已断开。程序会断开连接、结束会话缓存、把界面切回未连接，并弹一次提示；这条提示只弹窗，不写进日志窗口，技术细节留在控制台。

自动重连默认关闭。打开后最多重试 10 次，间隔是 3 秒 × 第几次、最长 30 秒；重连过程和结果同样不写日志。

WSL 分栏的收发、发送历史、日志缓存、工作流和终端模式都与串口分栏一致。映射设备被 detach 后，WSL 里的 `/dev/tty*` 会消失，读轮询连续失败就会走到上面的掉线判定。

## 常见问题

- **端口列表一直为空**：确认发行版在运行而不是只开了 Windows Terminal 窗口；回面板看映射状态和 WSL 路径是否出现；点刷新；必要时取消映射再重新映射；也可以在 WSL 里执行 `ls /dev/ttyUSB* /dev/ttyACM*` 确认节点存在。
- **映射复选框是灰的**：WSL 没在运行，先启动一个发行版。
- **映射失败**：看授权窗口是否被取消、usbipd 是否安装、设备是否还插着；设备被别的程序占用时先释放。
- **打开终端失败**：卡片上会弹提示，按提示检查 `wt.exe` 与发行版是否正常。
- **读不到发行版列表**：面板显示 WSL 原始报错，常见原因是 WSL 没装、没有发行版，或 `wsl --list --verbose` 被拒绝访问。
